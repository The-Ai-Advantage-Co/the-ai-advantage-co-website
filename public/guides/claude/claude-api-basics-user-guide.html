Core Concepts
Models, tokens, messages, and temperature â€” explained plainly

Before making your first API call, it helps to understand five key concepts. None of them require a technical background â€” they're just the vocabulary the API uses.

Models

A model is the specific version of Claude you're talking to. Different models have different strengths, speeds, and costs. You specify which one you want in every API call. (See Section 06 for a full comparison.)

Tokens

Claude doesn't count words â€” it counts tokens. A token is roughly 3â€“4 characters, or about Â¾ of a word. A 1,000-word document is approximately 1,300 tokens. API pricing is measured in tokens â€” both what you send (input) and what Claude responds with (output).

Quick estimate: 1,000 tokens â‰ˆ 750 words. A typical business email is 200â€“400 tokens. A detailed research brief might be 1,500â€“3,000 tokens.

Messages

Every API call is structured as a list of messages. There are three roles: system (sets the context and Claude's behaviour), user (your question or instruction), and assistant (Claude's response). Most simple calls just need a system message and a user message.

Temperature

Temperature controls how creative or precise Claude's responses are. It's a number from 0 to 1. A temperature of 0 gives consistent, deterministic responses â€” ideal for structured tasks like data extraction or classification. A temperature of 1 gives more varied, creative output â€” good for brainstorming or writing. The default (around 0.7) works well for most tasks.

Max Tokens

This setting limits how long Claude's response can be. Useful for keeping outputs short and costs predictable. If you don't set it, Claude will respond at whatever length it judges appropriate.

Your First API Call
What a request looks like and what comes back

An API call is simply a structured message sent to Anthropic's servers over the internet. Your tool sends it, Claude reads it, and a response comes back â€” typically in under two seconds. Here's what the request looks like, broken into plain language.

The Request

You send a POST request to https://api.anthropic.com/v1/messages with three things: your API key (in the headers), the model you want, and your messages.

Example Request (JSON body)
{
  "model":       "claude-sonnet-4-6",
  "max_tokens":   1024,
  "system":       "You are a helpful business assistant. Be concise.",
  "messages": [
    {
      "role":    "user",
      "content": "Summarise the key benefits of prompt caching."
    }
  ]
}

The Response

Anthropic sends back a JSON object containing Claude's reply, the model used, how many tokens were consumed, and the reason the response ended (e.g. reached max_tokens, or finished naturally).

The API is stateless â€” it doesn't remember previous calls. To build a back-and-forth conversation, you include the full message history (alternating user and assistant turns) in each request. Understanding Costs

API pricing is charged per million tokens, split between input tokens (what you send) and output tokens (what Claude sends back). Output tokens are typically more expensive than input tokens.

To estimate your costs: multiply your average message length (in tokens) by the number of calls you expect per month, then multiply by the per-token rate for your chosen model. Anthropic publishes current pricing at anthropic.com/pricing.

Best Practices
How to get consistent, high-quality results and keep costs in check

Getting reliable output from the API is mostly a function of how well you write your prompts and structure your calls. These practices apply whether you're using no-code tools or writing code directly.

Prompting

  • Be specific about format. If you want a bullet list, say so. If you want JSON output, specify the schema. Vague instructions produce variable results.
  • Give examples. A single before/after example in your system prompt often improves output quality more than extra instructions.
  • Set constraints explicitly. Max length, tone, what to exclude, what to do if unsure â€” spell these out upfront.
  • Use a role framing. "You are a senior marketing copywriter for a B2B SaaS company" outperforms "You are a helpful assistant" for most professional tasks.

Cost Management

  • Set a max_tokens limit on every call. Without it, Claude will respond at full length even for simple tasks.
  • Use Haiku for triage. Run a cheap Haiku call first to classify or filter requests, then route only complex ones to Sonnet or Opus.
  • Enable prompt caching if your system prompt is long and consistent across many calls.
  • Set a monthly budget cap in the Anthropic console. This prevents unexpected bills during testing.

Security

  • Never expose your API key client-side (e.g. in a website's JavaScript). Always make API calls server-side or through a backend proxy.
  • Rotate keys regularly and immediately if you suspect exposure.
  • Avoid passing sensitive user data (personal details, financial information) in API calls unless your security and privacy requirements are clearly understood.
âš ï¸
Test in a sandbox first. Run new prompts and workflows on sample data before connecting live systems. A prompt that works on one input may behave unexpectedly on edge cases.
