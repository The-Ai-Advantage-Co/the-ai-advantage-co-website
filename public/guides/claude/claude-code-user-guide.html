Claude Code — User Guide

A practical guide to using Claude Code — the AI-powered coding assistant that works directly in your terminal, understands your codebase, and helps you write, test, and ship code faster.

Version 1.0 Updated: April 2026 Audience: Developers & Technical Teams
01
What is Claude Code?
Your AI-powered coding assistant in the terminal

Claude Code is a command-line tool built by Anthropic that brings Claude directly into your development environment. Unlike chat-based AI, Claude Code has full access to your project — it reads your files, understands your codebase structure, runs your tests, and makes precise edits across multiple files in a single conversation.

It is designed for developers who want to move faster without giving up control. Claude Code explains every action it takes, asks before making significant changes, and works alongside your existing tools and workflows — not as a replacement for them.

💻
Terminal Native
Runs directly in your terminal. No browser tab, no copy-paste — Claude Code is in your workflow.
🔧
Codebase Aware
Reads your entire project structure, understands dependencies, and follows your conventions.
⚡
Command Execution
Runs tests, builds, and scripts — reads the output and acts on failures automatically.
🎯
IDE Integration
Works alongside VS Code, JetBrains, and other editors via the terminal panel.
💡
Think of it this way
Claude Code is like having a senior developer pair-programming with you in the terminal — one who has already read every file in your repo, knows your test suite, and can make changes across your entire codebase without you switching context.

What it is not

Claude Code is not an autopilot that rewrites your codebase unsupervised. It acts on your instructions, shows you what it plans to change before doing it, and keeps you in review mode for all significant edits. You remain the developer — Claude Code is the fast, knowledgeable assistant.

Getting Started
Install and authenticate in under five minutes

Claude Code installs as a global npm package. You need Node.js 18+ and an Anthropic account (Pro or higher plan, or API key).

1
Install Claude Code
Run npm install -g @anthropic-ai/claude-code in your terminal. This installs Claude Code globally so it's available in any project. Requires Node.js 18 or higher.
2
Navigate to your project
Use cd your-project-folder to move into the repository you want to work in. Claude Code reads files relative to the directory you launch it from.
3
Launch Claude Code
Type claude and press Enter. On first run, Claude Code authenticates with your Anthropic account. Follow the prompts — it opens a browser tab for OAuth, then returns you to the terminal.
4
Create your CLAUDE.md (recommended)
Add a CLAUDE.md file at your project root. This is where you tell Claude Code about your stack, coding conventions, test commands, and anything else it should know about your project. Claude reads this at the start of every session.
5
Start coding
You're ready. Type your first task in plain language — "add error handling to the user auth module" or "write tests for the payment service" — and Claude Code will read the relevant files and propose changes.
ℹ️
Good to know
Claude Code never sends your code to be stored or trained on. All file reads happen locally. Only the content you include in the conversation is sent to Anthropic's API for Claude to process.

What you can do straight away

📝
Write New Features
Describe the feature — Claude Code reads your codebase and writes it in your style.
🧪
Write & Run Tests
Generate tests, run them, read failures, and iterate until they pass — all in one session.
🔍
Understand Code
Ask "how does the auth flow work?" — Claude Code reads the files and explains it clearly.
🔄
Refactor Safely
Rename, restructure, and modernise code across multiple files with precision edits.

Core Capabilities
What Claude Code can do inside your project

Claude Code goes well beyond autocomplete or chat-based suggestions. It operates as an active participant in your development session — reading, writing, running, and reasoning about your code.

File Reading & Writing

Claude Code reads any file in your project — source code, config files, documentation, test suites, package manifests. When making changes, it performs precise edits (replacing specific text, adding specific lines) rather than rewriting whole files, so your git diff stays clean and reviewable.

💡
Always shows diffs before writing
For significant file changes, Claude Code shows you exactly what it plans to edit and asks for confirmation. You stay in review mode — you can approve, modify, or cancel any change before it's written to disk.

Test Running & Iteration

Claude Code can run your test suite, read the failure output, identify the root cause, fix the code, and re-run — iterating until tests pass or flagging issues it can't resolve. Works with Jest, Pytest, RSpec, Go test, and most standard test runners.

Build & Script Execution

It runs build commands, linters, type checkers, and custom scripts — then reads the output and acts on errors. Useful for catching compilation failures, type errors, or lint violations as part of a larger task.

Code Search & Analysis

Ask Claude Code to find all usages of a function, trace a data flow through your codebase, identify dead code, or map dependencies between modules. It searches across your entire project, not just open files.

📖
Multi-File Edits
Rename a function across every file that references it — in one instruction.
🗂️
Dependency Mapping
Understand what breaks before you refactor — Claude traces the dependency graph for you.
🐛
Debugging
Paste an error or stack trace and Claude Code reads the relevant source to diagnose it.
📋
Documentation
Generate inline comments, JSDoc, README sections, or architecture docs from your code.

Your Codebase Context
How Claude Code understands your project

Claude Code becomes significantly more useful when it understands your project's conventions, stack, and standards upfront. The primary way to give it this context is through the CLAUDE.md file.

The CLAUDE.md file

Place a CLAUDE.md file at the root of your project. Claude Code reads it automatically at the start of every session. Think of it as a one-page brief for a new developer joining your team.

💡
What to put in CLAUDE.md
Tech stack and versions · Build and test commands · Coding conventions (naming, structure, style) · What NOT to change (legacy areas, external contracts) · Deployment notes · Known gotchas or quirks in the codebase.

File Operations Reference

OperationWhat Claude Code doesExample instruction
Read Opens and reads any file in your project, including config and lock files. "Explain what the auth middleware in /src/middleware/auth.js does."
Write Creates a new file. Warns before overwriting existing files. "Create a new service file for email notifications at /src/services/email.js."
Edit Makes precise changes to existing files — replaces specific code without touching the rest. "Update the rate limit in config.js from 100 to 500 requests per minute."
Search Finds code patterns, function names, or text across your entire codebase. "Find every place we call the deprecated getUserById function."
Run Executes commands (tests, builds, scripts) and reads the output. "Run the test suite and fix any failing tests in the auth module."
⚠️
Destructive commands
Claude Code will not run commands that delete files or databases, reset environments, or push to remote repositories without explicit confirmation from you at each step. If a task requires such commands, Claude Code describes them and asks you to run them manually.

Slash Commands & Shortcuts
Quick reference for built-in session controls

Claude Code has a set of built-in slash commands for managing your session, switching models, and checking usage. Type any of these at the Claude Code prompt.

CommandWhat it does
/helpLists all available commands and their descriptions.
/clearClears the conversation context. Start fresh without restarting the session.
/compactSummarises and compresses the current conversation to free up context space for long sessions.
/reviewAsks Claude Code to review recent changes and flag anything that looks wrong or incomplete.
/costShows the token usage and estimated cost for the current session.
/modelSwitches between available Claude models (e.g. Sonnet for speed, Opus for complex reasoning).
/doctorChecks your environment setup — Node version, authentication status, MCP connections.
/initGenerates a starter CLAUDE.md by analysing your project structure.
/settingsOpens Claude Code settings — model preference, permissions, MCP configuration.
ℹ️
Custom slash commands
You can define project-specific slash commands in your CLAUDE.md. For example, define /deploy to run your deployment checklist, or /pr to auto-generate a pull request summary from recent changes.

MCP Servers
Extending Claude Code with live tool integrations

MCP (Model Context Protocol) servers let Claude Code connect to external services — databases, APIs, GitHub, Jira, documentation systems, and more. Once connected, Claude Code can read from and act on these tools as part of any coding task.

🐙
GitHub
Search issues, create PRs, review diffs, and manage labels without leaving the terminal.
🗄️
Databases
Connect to Postgres, MySQL, or SQLite. Claude Code reads schema and queries live data.
📚
Documentation
Pull live API docs, SDK references, or internal wikis directly into the conversation.
🔔
Jira / Linear
Read ticket descriptions and acceptance criteria to guide feature implementation.

Connecting an MCP server

1
Find a server
Run /settings and browse available MCP servers, or search the Anthropic MCP registry online.
2
Add to settings or CLAUDE.md
MCP servers can be configured globally (via settings) or per-project (via CLAUDE.md). Project-level config means the server only activates in that repo.
3
Authorise and use
Follow the one-time authorisation prompt for the service, then refer to it naturally in your tasks — "check the GitHub issue #482 and implement what it describes."
📌
Build your own
If no MCP server exists for your tool, Claude Code can help you build one using the MCP SDK. Ask: "Help me build an MCP server that connects to our internal metrics API."

Best Practices
How to work effectively with Claude Code

Claude Code is most effective when treated as a capable collaborator who needs clear task briefs — not as a magic autocomplete. The more context you give, the better the output.

Do this

  • Write a thorough CLAUDE.md before your first session. Ten minutes spent documenting your stack, test commands, and conventions saves hours of correction later.
  • Give Claude Code one clear task per message. "Add input validation to the signup form and write tests for it" is better than a vague "improve the signup flow."
  • Reference files and functions by name. "Update the rate limiter in /src/middleware/rateLimit.js" is faster than "update the rate limiter" — Claude Code doesn't have to guess which file you mean.
  • Use /compact in long sessions. As context fills up, compression keeps the session working efficiently without losing important earlier context.
  • Review diffs before approving writes. Claude Code shows you changes before writing them. Read the diff — catching an unexpected change before it hits disk is much faster than reverting it.
  • Commit frequently. After each significant change, commit to git. This gives you a clean undo history if a session goes in an unexpected direction.

Avoid this

  • Vague task descriptions. "Make this better" gives Claude Code nothing to work with. Describe the specific problem or outcome you want.
  • Skipping the CLAUDE.md. Without it, Claude Code makes assumptions about your stack and conventions that may not match your codebase.
  • Approving without reviewing. Claude Code is accurate but not infallible. Always review proposed changes, especially for edits across multiple files.
  • Letting context grow unbounded. Very long sessions degrade output quality. Use /compact or start a fresh session for a new task area.
💡
The task brief formula
WHAT to build + WHERE in the codebase + HOW it should behave.
Example: "Add rate limiting (WHAT) to the /api/auth/login endpoint in /src/routes/auth.js (WHERE) — max 5 attempts per minute per IP, return 429 with retry-after header (HOW)."

Troubleshooting
Common issues and how to fix them

claude: command not found

The global npm install didn't link correctly. Try npm install -g @anthropic-ai/claude-code again, then check that your npm global bin directory is in your PATH. Run npm bin -g to find the path and add it to your shell config.

Authentication keeps expiring

Run /doctor to check your auth status. If you're using an API key rather than OAuth, confirm the key is still active in your Anthropic Console. For team environments, consider using a shared service account key stored in your team's secrets manager.

Claude Code is reading the wrong files

Claude Code reads from the directory you launched it in. If it's picking up the wrong files, check your working directory (pwd) and relaunch from the correct project root. Adding a CLAUDE.md that names your key source directories also helps Claude prioritise the right areas.

Tests are failing after Claude Code's edits

Ask Claude Code directly: "The tests I ran are now failing — here's the output." Paste the test output and it will read the failing tests alongside the code it edited and propose a fix. This iterative loop is expected — it's faster than debugging manually.

Session context is getting too long

Run /compact to compress the conversation history into a summary while keeping important context. For a completely fresh start, use /clear. On very long tasks, starting a new session per major task area is a good habit.

Still stuck?
Run /doctor first — it catches most environment issues automatically. For product bugs, visit github.com/anthropics/claude-code. For coaching and workflow questions, contact The AI Advantage Co at theaiadvantageco.com.au.

Suggested Prompts
Copy and paste these to get started immediately

Not sure what to ask first? These prompts work across most stacks. Paste them into Claude Code and adjust the file paths and specifics to your project.

For Development Tasks

Feature Implementation
"Read the codebase structure and then implement [feature description]. Follow the existing patterns and conventions you find. Write tests alongside the implementation and run them before finishing."
Bug Fix
"Here's the error I'm seeing: [paste error/stack trace]. Find the root cause in the codebase, explain what's causing it, then propose and apply a fix. Run the relevant tests afterwards."
Test Coverage
"Analyse the test coverage for [file or module path]. Identify the most important untested cases, write tests for them using the existing test patterns, and run the suite to confirm they pass."
Refactoring
"Refactor [file or function] to [specific improvement — e.g. reduce duplication, extract a service, improve readability]. Don't change the public interface or behaviour. Show me the diff before writing."
Code Review
"Review the recent changes in this session. Flag anything that looks wrong, incomplete, or inconsistent with the rest of the codebase. Prioritise issues by severity."

For Codebase Understanding

Architecture Overview
"Read the project structure and give me a plain-English overview of how this codebase is organised — key modules, data flow, entry points, and anything non-obvious that a new developer should know."
Dependency Audit
"Find every place in the codebase that depends on [function/module/library]. List them with file paths and explain what each one does with it — I'm planning to change or remove it."
Generate Documentation
"Read [file or module] and generate inline JSDoc/docstring comments for every public function and class. Use clear, accurate descriptions based on what the code actually does — not generic placeholders."
CLAUDE.md Bootstrap
"Analyse this project and generate a CLAUDE.md file for me. Include: tech stack, build and test commands, folder structure overview, any conventions you observe, and the key files a developer should know about."
PR Summary
"Look at the files I've changed in this session and write a clear pull request description — what changed, why, what was tested, and any risks or follow-up items to flag for reviewers."

Your Roadmap
From first command to team-wide integration

Claude Code delivers value from the first session, but becomes significantly more powerful as you build habits and integrate it into your team's workflow. This roadmap takes you from install to full integration.

1
First productive session
Install Claude Code, write a basic CLAUDE.md, and complete one real task — a bug fix, a new function, or a test suite improvement. Prove it works on your codebase before building habits around it.
2
Refine your CLAUDE.md
After a few sessions, update CLAUDE.md based on what you've had to repeatedly explain. A good CLAUDE.md means Claude Code needs fewer clarifications — sessions become faster and more autonomous.
3
Add MCP integrations
Connect GitHub so Claude Code can read issues and create PRs. Add your database so it can inspect schema during refactoring. Each integration reduces context-switching and expands what Claude Code can do in a single session.
4
Build team conventions
Commit your CLAUDE.md to the repo so every team member gets the same context. Define shared custom slash commands for common tasks — PR summaries, deployment checks, test reporting. Standardise how the team uses Claude Code.
5
Integrate into your workflow
Use Claude Code in CI for automated code review, documentation generation, or test gap analysis. Build hooks that trigger on pre-commit or post-merge to keep quality consistent without manual effort.
📍
Where most teams start
The highest-leverage starting point is test writing. Teams that use Claude Code to generate and run tests first — before any feature work — build the habit of keeping test coverage high from day one. It also gives Claude Code immediate, verifiable feedback on its own output.
