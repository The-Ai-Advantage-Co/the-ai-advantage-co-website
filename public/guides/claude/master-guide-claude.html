What is Claude?
Anthropic's foundation model family

Claude is the family of foundation AI models from Anthropic. As of 2026, the lineup is Claude Opus 4.7 (the highest-capability model, with extended thinking, multimodal vision at 3.75 megapixels, and 94% computer-use accuracy), Sonnet 4.6 (the everyday workhorse — fast, strong reasoning, often preferred over previous-gen Opus in coding evals), and Haiku 4.5 (high-volume, low-latency tasks).

  • Strong everyday writing and editing
  • Top-tier coding (with Claude Code as the dedicated CLI)
  • Best-in-class tone handling for sensitive comms
  • Multimodal — vision, document understanding, code understanding
  • 1M token context window (Opus 4.6 and Sonnet 5, beta)
  • Tool use — bash, code, web fetch, computer use, custom MCP tools

Claude differs from the other major foundation model families in two consistent ways: tone-handling and reasoning calibration. Across independent evaluations through 2025-2026, Claude has been the strongest mainstream model for sensitive writing, nuanced editing, and prompts where the user wants the model to push back on weak framings rather than agree readily. The reasoning models (Opus 4.7, Sonnet 4.6 with extended thinking) are calibrated to think before answering hard prompts rather than producing confident-sounding shallow output.

What Claude is not best at: extremely high-volume cheap inference (Haiku 4.5 is competitive but not the cheapest in the market), specialised image generation (other tools are stronger), and the deepest agentic browsing (ChatGPT's Agent has a head start on autonomous web operation). The lineup is optimised for high-quality knowledge work, not low-cost commodity inference.

What makes the Claude 4 family distinctive

  • Tone-handling — best mainstream model for sensitive writing and tone calibration
  • Reasoning calibration — Opus 4.7 with xhigh effort genuinely thinks longer on hard problems
  • Computer use — 94% accuracy on insurance benchmarks (regulated tier)
  • 1M context — Opus 4.6 and Sonnet 5 hold an entire codebase or year of business data
  • Safety design — pushes back productively on weak prompts rather than agreeing reflexively

The Two New 2026 Tools
Memory and Advisor

Two new tools that meaningfully change how Claude works in practice:

  • Memory Tool — Claude can remember facts about a user, project, or workflow across conversations. Pair with the 1M context window for selective long-term recall.
  • Advisor Tool (May 2026 beta) — Set Sonnet or Haiku as executor with Opus advising on hard sub-problems. 11.9% cheaper per task, near-Opus quality on average — the cost-control unlock for agentic workflows.
🧰 WHEN TO USE WHICH TOOL
Memory: any work that recurs (weekly 1:1s, project workstreams, ongoing research). Advisor: any agentic workflow where most steps are routine and only a few are hard — typical pattern is 80-90% Sonnet executions with 10-20% Opus escalations.

Memory and Advisor are the two genuinely-new 2026 capabilities. Memory is the persistence layer — Claude remembers facts about a user, project, or workflow across conversations, without you having to re-brief every session. Advisor is the cost-control layer — Sonnet or Haiku executes routine work while Opus advises on hard sub-problems, producing near-Opus quality at meaningfully lower cost.

Both ship as opt-in. Memory is configured per scope (project memory, user memory). Advisor is a parameter on API calls and a toggle in Cowork Mode. Most users who try them keep them on after a week.

Skills and Plugins
Reusable working patterns

Skills are named, reusable workflows — short markdown files that encode a working pattern (a Code Review skill, a Brand QA skill, a Research Kickoff skill). Install once, invoke implicitly or explicitly across any session. Plugins extend Skills with code-bearing capabilities.

Skills are the underrated 2026 unlock. A skill is a short markdown file that encodes a working pattern — 'how I do code reviews', 'how I draft a brand-voice email', 'how I run a research kickoff'. Install once, invoke implicitly (Claude detects relevance) or explicitly ('use the brand-qa skill'). The compounding effect across a year of skill accumulation is meaningful.

Plugins extend Skills with code-bearing capabilities — tool integrations, custom data sources, computational primitives. Plugins are how Skills graduate from prompt patterns to actual capability expansion.

MCP — Model Context Protocol
Connecting Claude to your tools

MCP is the open protocol for connecting Claude to external tools and data sources. By 2026 it supports 6,000+ apps including GitHub, Slack, Jira, Google Drive, and Stripe. Native support in Claude desktop; custom MCP servers can be built in any language.

🔌 MCP FOR CUSTOM INTEGRATIONS
If your team uses a tool that's not in the public connector library, build a custom MCP server. The MCP Builder skill in Cowork Mode walks through the scaffolding. Most useful MCP servers are under 200 lines of code.

Safety and Refusals
What Claude won't do and why

Claude is trained to be helpful, honest, and harmless — refuses prompts that could lead to mass harm, CSAM, malicious code at scale, or targeted harassment. For dual-use topics (cybersecurity, medicine, etc.), Claude can help with legitimate professional framings if context is provided.

  • Refusal rate has dropped meaningfully through 2025-2026
  • Reframing legitimate work usually unblocks an over-cautious refusal
  • Claude pushes back productively on dishonest framings — this is a feature, not a bug

Claude for Writing, Editing & Tone Refinement

Pulling structured data from PDFs, contracts, invoices, scanned documents. Vision at 3.75 MP makes scanned-document workflows reliable.

  • Citation discipline — every claim cites the source

Claude for Sensitive and Nuanced Business Writing

Termination letters, public apologies, investor updates, regulatory communications. Where tone and restraint matter most.

  • The sensitive-writing brief: who-from, who-reads, what's the truth, what's off-limits

  • Public apologies — own the action, specify remediation, no 'sorry if'
  • Investor updates — lead with the number, show working, no hopium

Strategy work where Claude is your thinking partner, not your answer generator. Pre-mortems, root cause, stakeholder mapping, second-order effects.

  • Second-order effects: 'what's the consequence we'd see at 18 months?'
  • Stakeholder mapping — who's affected, what they care about, where interests conflict

Safety & Responsible Use
How Claude handles risk, what it refuses, and working with the safety design

Claude is trained to be helpful, honest, and harmless. Refusal rate dropped meaningfully through 2025-2026 — Claude is now substantially more helpful on dual-use prompts than the early Claude 3 era. Understanding what's behind a refusal makes Claude more productive to work with.

⚖️ WHEN CLAUDE WON'T BUDGE
For hard-line refusals (mass harm, CSAM, malicious code, targeted harassment), no reframing will or should work. Jailbreak attempts are increasingly ineffective and damage trust in your other prompts. Use Claude for legitimate work; the refusal categories are a feature, not a bug.

Claude Safety and Refusals

What Claude refuses, what it pushes back on productively, how to reframe legitimate work that gets caught up in over-refusal.

  • Refuses: mass-harm weapons, CSAM, malicious code at scale, targeted harassment
  • Pushes back on: framings that imply harm even when the immediate ask is fine
  • Reframing pattern: specific context + actual authority + concrete artefact
  • Dual-use topics work with explicit legitimate framing
  • Reporting: thumbs-down trains future versions

Common Mistakes & Fixes
What goes wrong — and how to avoid it

Most AI workflows that 'don't work' fall into one of these patterns. The fix is almost always sharper context and stricter review, not switching models or tools.

  • Treating Claude Master Guide as a finished answer rather than a draft to review
  • Vague prompts that don't specify audience, format, or what you want changed
  • Forgetting to give it context — the file, the brief, the constraints
  • Skipping the verify step — always check numbers, dates, names, and policy claims
  • Using it for tasks where a 30-second human action would be faster

✅ DO THIS

  • Provide context — the file, the brief, the audience, the constraints
  • Iterate; don't just accept the first output
  • Always review numbers, names, dates, and policy claims
  • Treat AI as a fast draft generator, not an answer engine
  • Capture what works so you can replicate it
  • Match the model to the task — fast modes for drafts, reasoning modes for analysis

❌ AVOID THIS

  • Sending AI output without reading it end-to-end
  • Vague prompts with no audience, format, or success criteria
  • Assuming AI can see files or context it hasn't been given
  • Using AI for tasks faster done manually in under a minute
  • Treating numbers, quotes, or citations as verified without checking
  • Defaulting to the slow reasoning mode for every task
