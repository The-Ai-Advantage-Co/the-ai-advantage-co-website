Claude Agents — User Guide

A practical guide to understanding and using Claude's agentic capabilities — autonomous, multi-step AI that plans, uses tools, and delivers finished results.

Version 1.0 Updated: April 2026 Audience: All Users
01
What is a Claude Agent?
Claude with the ability to plan, act, and deliver

A Claude Agent is Claude operating in agentic mode — not just answering a question, but planning how to accomplish a goal, using tools to gather information and take action, and delivering a finished result. Where standard chat is reactive, an agent is proactive.

You give it a goal. It figures out the steps, uses whatever tools are available — web search, code execution, file access, external APIs — and works through them until the task is complete. You stay in the loop and can redirect at any point.

🛠️
Tool Use
Agents browse the web, run code, call APIs, and read or write files — not just chat.
🧠
Multi-step Reasoning
Plans how to reach a goal across multiple steps, not just how to answer one question.
🤝
Human-in-the-Loop
Pauses and confirms before consequential or irreversible actions. You stay in control.
🔄
Orchestration
A single agent can coordinate subagents and tools, handling complex workflows end-to-end.
💡
Think of it this way
Standard Claude answers your question. A Claude Agent takes your brief, works through the problem, and hands you a finished result — the difference between asking for directions and having a driver.

What it is not

A Claude Agent is not an unsupervised background process that acts without your knowledge. Agents are invoked explicitly, show their work at each step, and require your approval before sensitive actions — sending emails, modifying records, or making financial transactions. The goal is powerful assistance, not autonomous operation without oversight.

Getting Started
Use Claude Agents right now — no setup required

You don't need to install anything or configure a pipeline to use Claude as an agent. The fastest path is simply giving Claude a goal-oriented, multi-step brief instead of a single question.

1
Open claude.ai on a Pro or Max plan
Agentic capabilities — extended reasoning, tool use, multi-step tasks — are available on Pro and Max. Developers can access the same capabilities via the Claude API with tool definitions.
2
Write a goal-oriented brief, not a single question
Instead of "What is X?", try "Research X, summarise the key findings, compare three approaches, and recommend the best option for a small business." This signals that you want Claude to plan and execute, not just answer.
3
Claude shows its plan — review before it executes
For multi-step tasks, Claude typically outlines its approach before starting. You can redirect, add constraints, or approve as-is. This keeps you in control of how the work gets done, not just what gets delivered.
4
The agent works through steps using tools
Claude searches the web, runs code, reads files, or calls APIs depending on what the task needs. You can watch it work in real time — each tool call is visible and explained.
5
Review the result and continue the conversation
The agent delivers its output and offers logical next steps. You can approve, ask for revisions, or redirect to a new task. The conversation continues from where it left off.
ℹ️
More advanced setups
For file access and connected business tools, use Cowork Mode on the Claude desktop app. For building custom agents programmatically, use the Claude Agent SDK or the API with tool use.

Core Capabilities
What Claude Agents can do beyond standard chat

Claude Agents combine reasoning, tool use, and the ability to take action across multiple steps. Here are the core capabilities that make agent tasks different from regular conversation.

Web Search & Live Research

Agents can search the web and retrieve current information — not just recall what they were trained on. This means your research brief returns results from today, not 2024. Claude cites sources, cross-references findings, and distinguishes between reliable and speculative information.

Code Writing & Execution

Agents write code and run it in an isolated sandbox, returning the actual output — not just the script. This is critical for data analysis, file processing, formula checking, and any task where you need a verified result, not an estimate. If the code errors, Claude debugs and retries automatically.

💡
Ask for results, not just code
Don't ask "write me a script to analyse this CSV." Ask "analyse this CSV and tell me the top 5 products by revenue this quarter." Claude writes the code and gives you the answer — the code is the means, not the end.

File Reading & Creation

With access to your workspace (via Cowork Mode or the API with filesystem tools), agents read your documents, pull relevant context, and write finished files directly to your folders. Word docs, spreadsheets, PDFs, Markdown — whatever format the task requires.

API & Tool Calling

Agents can call external APIs and services that you authorise — your CRM, your calendar, your payment platform. Each call is explicit and logged. The agent tells you what it's calling and why before it does it.

🌐
Web Research
Live search and retrieval — current information, not training data from the past.
💻
Code Execution
Write, run, debug, and verify — real output from a sandboxed environment.
📁
File Operations
Read, write, and edit documents in your workspace. Formats include DOCX, XLSX, PDF, and more.
🔌
Tool & API Calls
Call any authorised API — CRM, calendar, payments — with explicit confirmation.

Working with Context
How agents use and manage information across a task

Context is what an agent knows and can reference during a task. Understanding how context works helps you write better briefs and avoid common pitfalls in long or complex agent runs.

Context Reference

Context Type What the Agent Uses Practical Note
Conversation All messages in the current session, including tool results and Claude's own outputs. Up to ~200K tokens. Very long sessions may require starting a new conversation.
Uploaded Files PDFs, Word docs, CSVs, images, and code files attached directly to the conversation. Drag files into the chat. Claude reads them immediately and can reference them throughout the session.
Tool Results Output from web searches, code runs, API calls — added to context automatically as the agent works. Each tool result is visible in the conversation. The agent uses it to plan subsequent steps.
System Prompt A standing instruction set that configures the agent's behaviour, constraints, and persona. Available via the API or Cowork plugins. Sets the rules the agent follows throughout the session.
External Memory Files or databases the agent reads via tools (e.g., a Markdown knowledge base in your workspace). Store reference documents in your workspace folder. Claude reads them on demand when you reference them.
⚠️
Agents don't remember previous sessions
Each new conversation starts fresh. Context from previous sessions is not carried over automatically. Reference the specific files, briefs, or outputs from past sessions in your opening message — or save progress notes to your workspace folder between sessions.

Passing context efficiently

The most efficient way to give an agent context is a single, well-structured opening message: state the goal, reference the relevant files or data, specify constraints, and define the expected output format. This reduces back-and-forth and keeps the agent on track from the first step.

Agent Settings & Controls
How to configure and direct Claude Agents effectively

Whether you're using claude.ai, the API, or Cowork Mode, there are controls available to shape how your agent behaves. Here are the key levers and what they do.

Setting / Control What It Does Example
System Prompt Sets the agent's role, constraints, tone, and standing instructions for the session. "You are a legal research assistant. Always cite primary sources. Never give legal advice."
Tool List Defines which tools the agent is allowed to call. Restricting tools limits the agent's reach. Enable web_search and code_execution; leave out file_write for read-only tasks.
Max Turns Limits the number of steps the agent can take before pausing for human review (API setting). Set max_turns=5 for short contained tasks; higher for complex research workflows.
Human-in-Loop Defines which actions require your explicit approval before the agent proceeds. Require approval on all file writes, email sends, and CRM record updates.
Output Format Specifies the structure of the final result — crucial for consistent, usable outputs. "Return a markdown file with an executive summary, three key findings, and a recommended next action."
📌
Claude.ai vs API vs Cowork
On claude.ai, controls are set through your prompt. Via the API, you configure them programmatically with parameters and system prompts. In Cowork Mode, skills and plugins pre-configure agent behaviour for common tasks — you benefit from the settings without managing them manually.

How to connect a tool

1
Choose your integration method
On claude.ai, tools like web search and code execution are built in. For business tools (CRM, calendar, email), use Cowork Mode on the Claude desktop app. For custom integrations, use the API with MCP or tool definitions.
2
Authorise the connection
In Cowork Mode, go to Settings → Connectors and authorise each service. Each connector requires a one-time OAuth authorisation. API integrations require configuring your MCP server with the appropriate credentials.
3
Reference it in your prompt
Once connected, simply tell Claude what to do: "Search the web for...", "Check my HubSpot for...", "Run a Python script that...". Claude selects the right tool and calls it with your approval.
📌
Building a custom tool connection
If your tool isn't in the connector list, ask Claude: "Search for a [tool name] MCP connector." If one exists in the registry, Claude walks you through connecting it. If not, use the MCP Builder skill in Cowork Mode to build a custom connector from scratch.

Best Practices
How to get the best results from Claude Agents

Agents perform best when you treat them like a capable specialist who needs a clear brief — not a mind reader. The quality of your output is almost entirely determined by the quality of your instructions.

Do this

  • Write goal-oriented briefs. Describe the destination, not every step. "Produce a competitive analysis of the top three CRM platforms for a 20-person sales team" is better than "First search for CRM platforms, then compare them…"
  • Set constraints upfront. Tell the agent what it can and can't do: scope, format, tone, sources to use or avoid, and whether it should ask for approval before acting.
  • Let it plan before it executes. For complex tasks, ask Claude to outline its approach first. Review the plan, then approve. This catches misunderstandings before the agent does hours of work in the wrong direction.
  • Specify the output format precisely. "A markdown file with an executive summary, three sections, and a recommendation table" produces a far more usable result than "a summary."
  • Verify outputs before using them. Agents are highly capable but not infallible — particularly for calculations, citations, and factual claims. Build in a review step for any output going to clients or stakeholders.
  • Save useful briefs as templates. If you've written a prompt that produces a great result, save it. Agents are most valuable when you can reproduce high-quality outputs consistently.

Avoid this

  • Vague goals. "Do some research on AI" gives the agent no target. The less specific the brief, the more generic the output.
  • Sensitive credentials in the chat. Never paste API keys, passwords, or account numbers into the conversation. Use authorised connectors instead.
  • Assuming outputs are always accurate. Agents can hallucinate facts, misread data, or follow a flawed assumption all the way to the finish line. Critical outputs need human verification.
  • Running agents on critical systems unsupervised. Use human-in-the-loop controls for anything that modifies production data, sends communications, or touches financial records.
💡
The brief formula that works
Goal + context/data + constraints + output format.
Example: "Analyse the attached CSV of Q1 sales data (goal + data). Focus on products with margin below 20% (constraint). Return a ranked table with product name, revenue, margin, and one-line recommendation for each (output format)."

Troubleshooting
Common issues and how to fix them

The agent keeps asking clarifying questions instead of working

This means your brief was underspecified. Claude is trying to avoid wasting effort on assumptions that turn out to be wrong. Fix it by adding more detail upfront: the exact goal, the relevant context, any constraints, and the expected output format. A complete brief eliminates most clarifying questions before they arise.

A tool call failed or returned an error

Tool failures are usually caused by one of three things: an expired authorisation token, an API rate limit, or a network issue. For connector tools, go to Settings → Connectors and reconnect the affected service. For web search failures, ask Claude to retry — transient failures usually resolve on a second attempt.

The agent's output is inaccurate or includes hallucinated facts

Ask Claude to cite its sources for every factual claim, especially for research tasks. If a fact looks wrong, paste it back and ask Claude to verify it with a web search. For numerical outputs, ask Claude to run a verification step before finalising — it can check its own calculations with code execution.

The agent went off in the wrong direction mid-task

You can redirect at any point. Say "Stop — that's not what I meant. Let's go back to [specific point] and take a different approach." Claude will acknowledge the misdirection, confirm its new understanding, and restart from there. For complex tasks, asking for a plan upfront prevents this entirely.

The context window filled up mid-task

Very long agentic runs — especially those with many tool calls and large documents — can fill the context window. If this happens, save the key outputs to your workspace folder, start a new session, and reference those files directly. Keep context clean by working in focused task chunks rather than a single marathon session.

Suggested Prompts
Goal-oriented briefs ready to copy and run

These prompts are written as complete agent briefs — goal, context slot, constraints, and output format included. Replace the bracketed fields with your specifics and paste directly into Claude.

Competitive Research
"Research the top three competitors to [my product/company] in the [industry] space. For each one, find their pricing, key features, positioning, and recent news. Produce a comparison table and a one-paragraph summary of where we have a competitive advantage."
Market Intelligence
"Search for recent news and analyst commentary on [topic/market] from the last 90 days. Identify the three most significant trends, any emerging risks, and one market opportunity relevant to a [business type]. Save the findings as a structured briefing document."
Document Analysis
"Read the attached [contract/report/proposal]. Identify any clauses, terms, or figures that differ from our standard template. Produce a change summary table with: item, what it says, what our standard says, and recommended action. Flag anything that requires legal review."
Sales Prep
"I have a meeting with [company name] on [topic]. Search for recent news about them, check their LinkedIn and website for relevant context, and produce a one-page meeting brief: who they are, what they care about, likely objections, and three tailored talking points for our conversation."
Data Analysis
"Analyse the attached CSV. Calculate [specific metrics — e.g., revenue by product, churn by cohort, average deal size by channel]. Identify the top three insights and any anomalies worth investigating. Return a summary table plus a written interpretation I can share with the team."
Code Review
"Review the attached code for correctness, security vulnerabilities, and performance issues. For each issue found: describe the problem, explain the risk, and provide a corrected version. Prioritise by severity — critical, medium, low. Return a structured review document."
API Integration
"Search the [API name] documentation and write a working [Python/JavaScript] function that [specific action — e.g., retrieves all records updated in the last 7 days and formats them as a clean JSON array]. Include error handling, rate-limit awareness, and a test call with example output."
Data Pipeline
"Write a script that reads [input file/source], cleans the data by [specific rules — e.g., removing nulls, standardising date formats, deduplicating on email], and outputs a clean CSV with a summary of changes made. Run it on the attached test file and show me the output before saving."
Debugging
"Here is the error I'm getting: [paste error]. Here is the relevant code: [paste code]. Diagnose the root cause, explain why it's happening in plain English, and provide a corrected version. If there are related issues I should fix while I'm here, flag them too."
Technical Documentation
"Read the attached codebase / API spec and generate a developer reference document. Include: overview of what it does, authentication method, endpoint list with parameters and example responses, error codes, and a quick-start example. Write for a developer who is new to this system."
