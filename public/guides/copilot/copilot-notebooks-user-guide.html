What is Copilot Notebook?

AI that remembers your project — not just your last message

Copilot Notebook is a persistent AI workspace within Microsoft 365 Copilot. Unlike a standard chat session that resets every time, a Notebook keeps your project context alive — the documents you've added, the instructions you've set, and the reference material you've curated stay in place across every session.

For project work, this changes everything. Instead of re-explaining your project to Copilot every time you open it, the Notebook already knows: who the client is, what the brief says, what's been agreed, and how you want responses structured. You pick up exactly where you left off.

📌

Persistent Context

Add instructions, project briefs, key decisions, and reference docs once. Copilot uses them automatically in every interaction within that Notebook — no re-explaining required.

📂

Project Knowledge Base

Upload or link the documents that matter for this project. Copilot can reference, synthesise, and quote from them in any response — your project files become queryable knowledge.

✍️

Consistent Drafting

Generate project deliverables — emails, reports, status updates, proposals — with Copilot already knowing the project context, tone guidelines, and audience.

👥

Team Collaboration

Share a Notebook with your team so everyone works from the same AI-powered context. Consistent answers, consistent outputs — no matter who's asking.

One Notebook Per Project

The most effective pattern is one Notebook per active project. Each Notebook holds that project's context, documents, and instructions — separate from everything else. When the project ends, the Notebook becomes a searchable archive of all the AI-assisted work done on it.

02

Setting Up a Notebook

Create your project workspace and configure the context Copilot will always use

Setting up a Notebook takes around 10 minutes but pays back every time you open it. A well-configured Notebook means Copilot already understands the project before you ask your first question.

1

Open Microsoft 365 Copilot and create a new Notebook

In the Microsoft 365 Copilot app, select Notebooks from the left nav. Click "New Notebook," give it a clear project name (e.g. "Contoso Rebrand Q3" or "Annual Report 2026"), and choose whether it's personal or shared with your team.

2

Write your project instructions

The instruction block is the most important part of your Notebook. This is where you tell Copilot everything it needs to know about the project: what it is, who the stakeholders are, the tone to use, what to prioritise, and any constraints. Write it as if briefing a new team member on day one.

3

Add your reference documents

Link or upload the core project files: the brief, scope of work, key decisions log, brand guidelines, or any document Copilot should be able to reference. These become permanently available within this Notebook.

4

Test with a calibration prompt

Before using the Notebook for real work, test it: "Based on the project context and documents in this Notebook, give me a 5-bullet summary of the project goals, key constraints, and success criteria." The response shows you whether the context is complete and accurate.

Writing Effective Project Instructions

Your instruction block is what Copilot uses every time it responds. The more precise and complete it is, the less you'll need to specify in individual prompts.

03

Building Your Project Knowledge Base

Add documents, decisions, and reference material that Copilot can always access

The more relevant material you add to a Notebook, the more accurate and useful Copilot's responses become. Think of the knowledge base as the project's source of truth — anything Copilot might need to reference, quote, or reason from should be here.

📋

Project Foundation Docs

The brief, scope of work, proposal, or statement of work. These define what the project is and what success looks like — Copilot uses them to ground every response.

📝

Decisions & Notes

Meeting notes, decisions logs, and agreed changes. Add these as they accumulate — Copilot will reference the latest version, keeping its responses current with the project state.

📊

Data & Research

Reports, research papers, competitor analysis, or market data. Copilot can synthesise and quote from these when drafting analysis or recommendations.

🎨

Style & Brand Guides

Brand guidelines, tone of voice docs, style guides. Add these and instruct Copilot to follow them — output will align with your organisation's standards without reminders.

What to Add — and When

Document TypeAdd WhenWhy It Helps
Project brief / SOWAt setup — Day 1Grounds all Copilot responses in the agreed scope and objectives
Meeting notesAfter each key meetingKeeps Copilot current with decisions and changes — prevents stale advice
Stakeholder commsAs received / sentCopilot can reference tone, agreed positions, and open commitments
Research & dataWhen gatheredEnables Copilot to synthesise findings rather than relying on your memory
Draft outputsAfter team reviewCopilot can build on approved drafts rather than starting from scratch

ℹ️
Quality Over Quantity

Adding too many documents can dilute Copilot's focus. Prioritise the 5–8 most important files for the current phase. Archive documents that are no longer relevant to active work — you can always add them back if needed. A focused knowledge base produces better responses than a cluttered one.

04

Research & Synthesis

Use Copilot to analyse, compare, and surface insights from your project documents

Once your knowledge base is populated, Copilot can do analytical work that would take hours manually — comparing documents, identifying gaps, synthesising research, and extracting the information that matters most for your current task.

1

Ask Copilot to compare documents

"Compare the project brief with the latest meeting notes. What has changed from the original scope, and what has been formally agreed vs what is still being discussed?"

2

Surface gaps and contradictions

"Review all documents in this Notebook. Are there any contradictions between the brief and the decisions log? Are there any topics the brief raises that haven't been resolved in the meeting notes?"

3

Extract structured information

"From all the meeting notes in this Notebook, create a table of: Decision made | Date | Owner | Status. Include only decisions that have been formally agreed."

4

Synthesise for a specific audience

"Summarise the key project findings from the research documents in this Notebook into a 200-word executive summary suitable for someone who hasn't been involved in the project."

05

Drafting Project Deliverables

Generate status updates, reports, emails, and proposals — context already loaded

With your Notebook configured, drafting project deliverables becomes dramatically faster. Copilot already knows the project, the client, the tone guidelines, and the current status — so a "draft the weekly update" prompt produces something substantially closer to finished than the same prompt in a blank chat.

📊

Status Reports

"Draft this week's project status report. Use the RAG format. Base it on the most recent meeting notes and decisions log. Flag the two biggest risks with owners and mitigation steps."

📧

Stakeholder Emails

"Draft an email to the Contoso steering group summarising where we are against the brief, what we've decided this week, and what we need their input on by Friday."

📋

Meeting Agendas & Packs

"Create the agenda for next week's project review. Include the three open decisions that need resolution and build in 10 minutes for risks. Format as a Word-ready table."

🔄

Change Requests & Briefings

"Draft a change request for the scope addition discussed in the 14 May meeting notes. Capture what's changed, the impact on timeline and budget, and what approval is needed."

The Deliverable Drafting Workflow

1

Update the Notebook before drafting

Before asking Copilot to draft anything, check that the most recent meeting notes and decisions are in the Notebook. Copilot drafts from what's there — stale documents produce stale drafts.

2

Specify the format and audience

Tell Copilot the format (email, bullet list, Word table, slide content), the audience (client, internal team, steering group), and the length (under 300 words, one A4 page). These three inputs shape output more than anything else.

3

Review, refine, and confirm facts

Always verify the specific figures, names, and dates Copilot includes. It references your documents accurately, but project docs evolve — any detail that's changed since the last update may not be reflected.

4

Add the approved draft back to the Notebook

Once a deliverable is reviewed and approved, add it to the Notebook as a reference document. Future drafts will build on approved outputs rather than starting from scratch — maintaining consistency across the project lifecycle.

✨
Instruct Once, Draft Many Times

Add your deliverable templates to the instructions: "When drafting status reports, always use the RAG format with sections: Summary / Progress / Risks / Decisions Needed. Never include assumptions as facts." One instruction shapes every status report for the life of the project.

06

Managing Long-Running Projects

Keep your Notebook current as the project evolves — week by week

A Notebook is most valuable on long-running projects where context accumulates over weeks or months. The discipline is keeping it current — a Notebook that's three weeks out of date gives outdated answers. A well-maintained Notebook effectively gives you a project assistant with perfect memory.

The Weekly Notebook Maintenance Routine

1

Add this week's meeting notes

Upload or paste notes from all project meetings held this week. Even rough notes are useful — Copilot can extract the decisions and actions from them. Use the naming convention: "YYYY-MM-DD — [Meeting Name]" to make documents easy to reference.

2

Update the decisions log

If you maintain a formal decisions log as a document, update it and re-upload. Ask Copilot: "Based on this week's meeting notes, what new decisions were made? I'll add them to the decisions log." Use Copilot to populate the log for you.

3

Remove or archive outdated documents

Remove early drafts once a final version exists. Remove superseded briefs. A document that's been replaced causes confusion — Copilot may reference the old version. Keep only the most current version of each document type.

4

Run a weekly project pulse check

End each week with: "Based on all documents in this Notebook, what are the top 3 risks heading into next week, what decisions are still outstanding, and is there anything the team has committed to that hasn't been tracked?" This 2-minute prompt surfaces what would otherwise slip.

💡
Notebook as Project Archive

When the project completes, don't delete the Notebook. Archive it. A project Notebook is a complete, searchable record of everything the team produced, decided, and discussed — with AI-powered recall. "What approach did we take on the Contoso project for X?" becomes a question you can answer in 30 seconds, months later.

Team Collaboration

Share your Notebook so the whole team works from the same AI context

A shared Notebook means your entire team works with the same project context, the same reference documents, and the same AI behaviour. This eliminates the inconsistency that happens when everyone is using Copilot separately — and ensures that new team members get up to speed from the same source of truth.

Collaboration Patterns

🆕

Onboarding New Team Members

Share the Notebook and give them the onboarding prompt: "Summarise the project for a new team member joining today." They're fully briefed in minutes, not hours.

🔄

Handovers & Cover

When someone is on leave, the covering colleague has full project context immediately. No lengthy handover doc needed — the Notebook is the handover.

🤝

Cross-Functional Teams

Different disciplines (legal, finance, comms) can use the Notebook to ask project questions without needing a team member to brief them each time.

📋

Consistent Deliverables

Everyone generates status updates, emails, and reports from the same context and instructions — so all team output sounds consistent regardless of author.

🔒

Owner Controls

The Notebook owner controls who can edit instructions and add documents, vs who can only read and interact. Protect the context from accidental changes.

📊

Meeting Prep

Before project meetings, team members each ask: "What should I focus on for today's review based on my role?" Copilot gives role-specific prep from shared context.

⚠️
Nominate One Notebook Owner

Without a designated owner, shared Notebooks accumulate duplicate documents, conflicting instructions, and outdated material. One person should own the Notebook — maintaining instructions, approving document additions, and running the weekly cleanup. Typically the project lead or delivery manager.

08

Common Mistakes & Fixes

What goes wrong — and how to fix it

Copilot gives outdated or inaccurate answers
The most common cause is stale documents in the Notebook. Copilot references what's there — if the meeting notes from three weeks ago say one thing, and an undocumented decision changed it since, Copilot doesn't know. Maintain a weekly update habit: add new meeting notes, update the decisions log, and remove superseded document versions. Also try: "Based on the documents in this Notebook, are there any areas where information might be outdated or missing?"
The Notebook context is ignored and responses feel generic
Check your instruction block — is it specific enough? Vague instructions like "this is a marketing project" give Copilot very little to work with. Rewrite instructions to be concrete: who the client is, what the project deliverable is, what tone to use, and what Copilot should always or never do. Also verify that documents are correctly linked and accessible — if a document failed to attach, Copilot has no awareness of it.
Team members are getting inconsistent answers from the same Notebook
This usually happens when team members are phrasing prompts very differently, or when someone has edited the instructions. Check the instruction block for recent changes and restore consistency. Also consider adding standard prompt templates to the Notebook instructions: "When asking for a status update, use this prompt format: [template]." Standardising the prompt standardises the output.
The Notebook has too many documents and responses are becoming unfocused
A Notebook with 20+ documents of varying relevance dilutes Copilot's focus. Archive documents from completed project phases. Remove duplicates and old drafts. Add a note to your instructions: "Prioritise the Project Brief, latest meeting notes, and current decisions log when answering questions." Explicit prioritisation in the instructions helps Copilot weight the most important documents.
A new team member edited the instructions and broke the Notebook behaviour
This is why Notebook ownership matters. Set permissions so only the Notebook owner can edit instructions. Keep a copy of your original instruction block in a separate doc so you can restore it quickly. Consider version-noting major instruction changes in the instructions themselves: "Updated 14 May — added client approval workflow section."

✓ Do This

  • Write specific, detailed instructions at setup
  • Update the Notebook after every project meeting
  • Nominate one owner for shared Notebooks
  • Archive — don't delete — completed Notebooks
  • Run a weekly pulse-check prompt to surface gaps

✗ Avoid This

  • Vague instructions that don't specify client, tone, or scope
  • Leaving outdated documents alongside newer versions
  • Sharing edit access with the whole team without an owner
  • Using a Notebook for unrelated projects
  • Trusting outputs without checking document currency

Suggested Prompts

Ready-to-use prompts for project work and team collaboration

Weekly Project Pulse Check
Based on all documents in this Notebook, give me: (1) the top 3 risks heading into next week with owners, (2) any decisions that are still open and need resolution, (3) any commitments made in meeting notes that haven't been captured in the decisions log, and (4) anything that contradicts the original project brief. Be specific and cite which document each item comes from.
Draft a Status Report
Based on the project documents and meeting notes in this Notebook, draft this week's status report in RAG format. Sections: (1) Overall Status [Red/Amber/Green with one sentence reason], (2) Progress This Week [3 bullets], (3) Key Risks [2 risks with owner and mitigation], (4) Decisions Needed [what requires input and from whom, by when]. Audience: [steering group / project sponsor]. Under 400 words.
Scope Change Assessment
A change has been requested: [describe the change]. Based on the project brief and documents in this Notebook, assess: (1) Is this within the original scope or a change? (2) What is the likely impact on timeline and budget? (3) What decisions or approvals would be needed to proceed? (4) Are there any dependencies or risks this change creates? Be specific and reference the relevant sections of the brief.
New Team Member Onboarding Brief
I'm [name], joining this project today as [role]. Based on everything in this Notebook, give me a structured briefing: (1) What is this project and what does success look like? (2) Where are we right now — what phase, what's been done, what's coming? (3) What are the key decisions already made that I need to know about? (4) What are the current open risks or issues? (5) What should I focus on in my first two weeks?
Meeting Agenda from Notebook State
Based on the current state of this Notebook — open decisions, risks, and this week's progress — create the agenda for [meeting name] on [date]. Include: time allocated to each item, who should lead each section, and what outcome we need from each agenda point. Flag any agenda item where we don't yet have enough information to make a decision — note what's missing.
Handover Summary for Cover
I'm handing over to [name] while I'm away from [date] to [date]. Based on this Notebook, create a handover briefing covering: (1) where the project is right now, (2) what's happening during my absence — meetings, deadlines, milestones, (3) decisions or actions that will need attention, (4) who to contact for what, and (5) anything that could go wrong and how to handle it. Make it self-contained — [name] hasn't been involved in this project before.

Your Roadmap

From first Notebook to AI-powered project management

1

First Notebook

Set up a Notebook for one active project this week. Write a proper instruction block, add the brief and latest meeting notes, and run the calibration prompt to verify context.

2

Weekly Rhythm

Build the habit of updating the Notebook after every project meeting. Run the weekly pulse-check prompt every Friday. Within two weeks, you'll see why this matters.

3

Team Notebook

Migrate to a shared Notebook with your project team. Nominate an owner. Use it for onboarding, handovers, and consistent deliverable drafting across the team.

4

Portfolio View

Run multiple project Notebooks simultaneously. Use cross-Notebook queries to surface resource conflicts, shared risks, and patterns across your project portfolio.

✨
The Goal: AI That Knows Your Project As Well As You Do

The best Notebook is indistinguishable from a brilliant project assistant who's been on the project from day one — knows every decision, every commitment, every risk, and every stakeholder. That doesn't happen automatically. It happens because someone took 10 minutes at setup and 5 minutes each week. Start that habit on one real project this week.
