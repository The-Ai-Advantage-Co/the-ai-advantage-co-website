What is a Copilot Agent?

AI that doesn't just answer questions — it takes action

A Copilot Agent is an autonomous AI assistant that you configure to handle a specific job. Unlike standard Copilot — which responds to prompts on demand — an Agent can monitor triggers, retrieve data from connected sources, run multi-step workflows, and take actions across Microsoft 365 and beyond, with minimal human input.

Think of it as hiring a specialised AI team member with a defined role. You tell the Agent what it knows, what it can do, and when to act. Then it operates — answering questions from colleagues, routing requests, generating documents, sending notifications, or updating records — consistently and at scale.

🎯

Purpose-Built

Each Agent is scoped to a specific role — helpdesk assistant, onboarding guide, project tracker, or policy advisor. Focused agents outperform general ones.

🔗

Connected to Your Data

Agents can access SharePoint, Teams, Outlook, Dataverse, and external APIs. They answer from your actual information — not generic AI knowledge.

⚡

Action-Capable

Beyond answering questions, Agents can create tasks, send emails, update records, trigger Power Automate flows, and interact with external systems.

📡

Always Available

Deployed to Teams, SharePoint, Outlook, or a web channel, your Agent is available to colleagues 24/7 — handling routine requests without human handoff.

03

Building Your First Agent

From idea to deployed agent in Copilot Studio — step by step

Copilot Studio is the no-code builder for custom agents. You can create an agent by describing it in plain English — Copilot Studio generates the initial structure — then refine it by adding knowledge sources, configuring topics, and connecting actions. Most first agents can be built and tested in under an hour.

Before You Build — Define Your Agent
📋

Who will use it
Who is the audience for this Agent?e.g. "All staff via Teams"
What it needs to know
What data / docs should it access?e.g. "IT policies SharePoint site"
⬡ What actions should it take?

Beyond answering questions, should your agent create tickets, send emails, update lists, trigger approvals, or escalate to a human? Define this before building — it determines which connectors you need.

Building in Copilot Studio
1

Open Copilot Studio

Go to copilotstudio.microsoft.com (or open it from the M365 app launcher). Sign in with your work account. You'll see your agent library and a 'Create' button.

2

Describe your agent

Click 'Create' and type a plain-English description: "An agent that answers IT helpdesk questions from staff, using our IT policy documentation on SharePoint." Copilot Studio generates a draft agent with suggested topics, a name, and an initial system prompt.

3

Add knowledge sources

In the Knowledge tab, connect the SharePoint sites, OneDrive folders, or external URLs your agent should draw from. The agent will answer questions grounded in these sources — not from general AI knowledge.

4

Configure topics and responses

Topics define how your agent handles specific requests. Review the auto-generated topics, add any gaps, and set fallback behaviour for questions outside scope — either a polite decline or escalation to a human.

5

Test in the built-in test panel

Use the test chat on the right side of Copilot Studio to try common questions. Check for accuracy, tone, and coverage. Adjust topics or knowledge sources based on what the agent gets wrong.

6

Publish and deploy

When you're satisfied, click Publish. Then go to Channels to deploy: Teams, SharePoint, Outlook, a custom web chat widget, or the M365 Copilot chat interface.

📝
Write a strong system prompt

The system prompt is the Agent's "job description" — it shapes every response. Be specific: define the role, the tone, what the agent should and shouldn't do, and how it should handle out-of-scope questions. A strong system prompt is the single biggest factor in agent quality.

Connecting Actions & Data

Give your agent access to real information and the ability to act

An agent without connected data can only answer from its own training — which means generic, often unhelpful responses. Connected agents answer from your actual SharePoint, your real policies, your live systems. And agents with actions can do things, not just say things.

Actions — What Your Agent Can Do
📬

Send Messages & Emails

Trigger Teams messages or Outlook emails as part of a workflow — confirmations, escalations, notifications, follow-ups.

📋

Create & Update Records

Add tasks to Planner, update SharePoint lists, create Dataverse records, log interactions — any writeable system.

⚡

Trigger Power Automate Flows

Call any Power Automate flow as an action — approval requests, multi-system updates, complex conditional logic.

🔌

Call External APIs

POST data to external systems, retrieve live information from third-party tools, or trigger webhooks in other platforms.

⚠️
Actions need careful scoping

Every action your agent can take is something it might do incorrectly. Scope actions narrowly — a helpdesk agent should log tickets, not delete them. Add confirmation steps for irreversible actions and test edge cases before deploying broadly.

Publishing to Teams — Step by Step
1

Publish the agent

In Copilot Studio, click Publish. This creates a version of the agent that can be deployed. Unpublished agents are test-only — they can't be shared externally.

2

Open the Teams channel

Go to Channels → Microsoft Teams → Turn on Teams. This creates a Teams app package for your agent. You can customise the app icon and description here.

3

Submit for admin approval (if required)

In most organisations, Teams apps must be approved by an admin before appearing in the app catalogue. Submit the agent app and notify your Teams or M365 admin to approve it in the Teams Admin Centre.

4

Share with your team

Once approved, colleagues can find the agent in the Teams app store and add it. You can also share a direct install link or ask an admin to pre-install it for specific Teams or the whole org.

💡
Start with a pilot group

Before org-wide deployment, run a 2-week pilot with 10–20 users who represent your target audience. Collect their questions, review where the agent struggled, and refine knowledge sources and topics. You'll catch 80% of issues before they affect everyone.

Governance & Controls

Permissions, responsible AI, and keeping agents in bounds

Agents that access company data and take actions on behalf of users require clear governance. Microsoft builds responsible AI guardrails into Copilot Studio by default — but you're responsible for how you configure and deploy agents in your organisation.

Responsible AI Principles for Agents

Do This

  • Define clear scope — what the agent should and shouldn't handle
  • Build an escalation path to a human for complex or sensitive issues
  • Tell users they're talking to an AI agent
  • Review agent analytics regularly for unexpected behaviour
  • Test edge cases before broad deployment
  • Document what data sources and actions the agent uses

Avoid This

  • Don't give agents access to data broader than their task requires
  • Don't deploy agents that can take irreversible actions without human review
  • Don't let agents make decisions about individual people (HR, performance)
  • Don't skip the pilot phase before org-wide rollout
  • Don't connect agents to financial transaction systems without strict controls
  • Don't ignore user feedback — complaints signal real problems
⚠️
Agents inherit user permissions

A Copilot Agent can only access data that the user interacting with it has permission to see. It cannot bypass SharePoint permissions, break data residency rules, or access confidential content the user is not authorised for. Governance starts with your data permissions, not just the agent configuration.

Advanced Techniques

Multi-step agents, chaining, orchestration, and Power Platform integration

Once you have a working agent, the next level is making it smarter: handling complex multi-step conversations, handing off between agents, integrating deeply with Power Automate, and using adaptive cards to create rich interactive responses inside Teams.

Multi-Step Conversations

A basic agent answers one question at a time. An advanced agent guides the user through a structured flow — gathering information, validating inputs, and taking action at the end. Design these as topics with multiple "nodes": a question node, a condition node, and an action node.

🔀

Conditional Logic

Branch conversations based on user input. "Is this a hardware or software issue?" routes to different knowledge sources and escalation paths automatically.

🤝

Agent Handoff

When a request exceeds scope, transfer to a human agent or a specialist AI agent. Copilot Studio supports seamless handoff with context preserved.

🎴

Adaptive Cards

Return rich formatted cards in Teams — with buttons, forms, and dropdowns — instead of plain text. Users interact with your agent through structured UI elements.

🔁

Power Automate Chaining

Trigger multi-step Power Automate flows from agent actions — update three systems, send an approval, and log the outcome, all from a single user request.

Common Mistakes & Fixes

The most frequent agent failures — and how to prevent them

My agent gives generic answers instead of using our documents
The knowledge sources aren't connected, are stale, or the agent can't access them. Check the Knowledge tab in Copilot Studio — confirm sources are indexed (green status). If a SharePoint site is showing an error, verify the agent's service account has read access to that site. Re-index after fixing access.
The agent answers questions it's supposed to decline
Your system prompt isn't scoped tightly enough. Add explicit out-of-scope instructions: "You are an IT helpdesk agent. Do not answer questions about HR, finance, or any topic outside IT systems and policy. For those, respond: 'I'm not set up to help with that — please contact [team].'" Be explicit; the agent won't infer limits.
Users can't find the agent in Teams
The agent app likely hasn't been approved by your Teams admin yet, or it's only been made available to specific users. Check the Teams Admin Centre under 'Manage apps' — look for the agent and confirm its status. Ask your admin to approve and push it to the right audience.
The agent action fails silently — nothing happens when it should take action
Test the action independently in Power Automate or the connector settings first. Common causes: the agent's service account doesn't have write permissions to the target system; the flow is disabled; or a required field isn't being passed from the conversation. Check the agent's analytics in Copilot Studio for error logs.
The agent hallucinates — it makes up information not in the knowledge sources
Add this instruction to your system prompt: "Only answer questions using the provided knowledge sources. If you cannot find the answer in the knowledge sources, say 'I don't have that information — please contact [team].' Never guess or infer information not explicitly in your sources." Also check that relevant documents are actually indexed.
My agent worked in testing but fails in production
The most common cause is that the test environment uses your personal credentials (which have broad access), while production uses the agent's service account (which may not). Validate that the service account has access to every knowledge source and action target before publishing. Run a pre-deployment checklist against a non-admin test user account.

Suggested Prompts

Ready-to-use prompts for designing, building, and improving agents

System prompt template
You are [Agent Name], a specialist assistant for [Organisation Name]. Your job is to [specific role — e.g. answer IT helpdesk questions from staff]. You have access to [knowledge sources]. Always answer from these sources — never guess or use general knowledge. If a question is outside your scope, say: "I'm not set up to help with that — please contact [team/email]." Keep answers clear, concise, and professional. When you're unsure, say so and suggest who can help.
Scoping a new agent (use with Copilot Studio AI builder)
I want to build a Copilot Agent that [job description — e.g. helps new staff answer onboarding questions]. The agent will be used by [audience] via [channel — e.g. Teams]. It should draw from [knowledge sources] and be able to [specific actions]. What topics should I configure, what knowledge should I add, and what actions will it need? Also flag any risks or limitations I should design for.
Defining out-of-scope behaviour
Help me write the "out of scope" section of a system prompt for a [type] agent. The agent should handle [in-scope topics]. For anything outside these areas, write response scripts that are polite, helpful, and route the user to the right alternative. Include at least 6 specific examples of out-of-scope topics with tailored redirect messages.
Reviewing agent conversation logs
Here are conversation logs from our Copilot Agent over the past [time period]: [paste logs]. Analyse these for: (1) questions the agent answered incorrectly or incompletely, (2) questions that fell outside its scope but shouldn't have, (3) patterns in what users are actually asking versus what we designed the agent for, and (4) specific improvements to the system prompt or knowledge sources that would fix the top 3 issues.
Improving a weak system prompt
Here is the current system prompt for our [agent name] agent: [paste prompt]. Users are reporting that it [specific problem — e.g. gives vague answers / goes off-topic / doesn't escalate correctly]. Rewrite the system prompt to fix these issues while keeping the same core role and scope. Explain what you changed and why.
Designing an escalation flow
Design an escalation flow for our [type] agent. When should it escalate to a human? What information should it collect before escalating — so the human receiving the handoff has full context? Write the escalation topic logic, including: the trigger conditions, the data-gathering questions, the handoff message to the user, and the notification to the human team.
