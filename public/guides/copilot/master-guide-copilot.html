What is Microsoft 365 Copilot?
AI assistance embedded in the M365 suite

Microsoft 365 Copilot is the AI layer embedded in Word, Excel, PowerPoint, Outlook, Teams, OneNote, SharePoint, and more. It's powered by the GPT-5 family combined with Microsoft Graph (the data layer that connects your M365 content). Two tiers exist: a free Copilot Chat tier (standalone chat with web grounding), and a paid Microsoft 365 Copilot tier (in-app panels + Graph access).

  • Write — draft emails, reports, presentations, documents
  • Summarise — condense long threads, transcripts, and documents
  • Analyse — natural-language data analysis in Excel
  • Chat — query across your M365 content via Copilot Chat
  • Agentic — multi-step task execution in Word, Excel, PowerPoint

Think of Copilot as a layer that sits on top of your existing Microsoft 365 work — it doesn't replace Word, Excel, or Teams; it adds an AI panel to each of them and a standalone Chat surface that spans all of them. The model behind the scenes is the GPT-5 family, with Microsoft's MAI models for certain workloads. The data layer is Microsoft Graph, which is what lets Copilot reference your emails, calendar, files, and meetings without copying them anywhere.

What's distinctive is the combination: a high-capability model plus tenant-grounded data plus deep app integration. Standalone chat tools (ChatGPT, Claude, Gemini) match Copilot on raw capability, but only Copilot can summarise the email thread you're currently reading, draft a reply that references your last meeting, and post the action items to your Teams channel — all in one flow.

When Copilot is the right tool — and when it isn't

Copilot wins on in-flow M365 work: drafting in your inbox, analysing your spreadsheet, summarising your meeting. It is not the right tool for open-canvas reasoning (where ChatGPT's Canvas or Claude's Cowork Mode win), for tasks outside your tenant data, or for tasks where the answer comes from the public web only (Copilot Chat has web grounding but is not optimised for it).

  • Use Copilot when the work is grounded in your M365 content
  • Use a standalone AI tool when the work is open-canvas reasoning or research
  • Use both — most organisations end up deploying Copilot plus one of ChatGPT/Claude

The Two Tiers
Know which tier you have

Understanding the two-tier model is the single biggest reason adoption succeeds or fails. Free Copilot Chat is what's included with eligible Microsoft 365 commercial subscriptions; paid Microsoft 365 Copilot is the add-on that unlocks the in-app panels and tenant data access. Most rollouts get this wrong by assuming licensing the paid tier is the start of the journey — but the free tier is usually already there, waiting to be used.

The Core Apps
Where Copilot lives across M365

Each M365 app has its own Copilot surface, optimised for the kind of work that happens there. Outlook's Copilot is built around email — summarising threads, drafting replies, coaching tone. Excel's Copilot is built around data — analysing tables, writing formulas, generating charts. Teams' Copilot is built around meetings and conversations — recaps, real-time prompts, channel summaries. The pattern is consistent: open the app, look for the sparkle icon, and the right Copilot shows up.

  • Outlook — email drafting, summarisation, scheduling, coaching
  • Teams — meeting recap, real-time meeting assistance, channel summaries
  • Word — draft, rewrite, summarise, transform, with Agent Mode GA
  • Excel — analyse data, formula assistance, charts, Python integration
  • PowerPoint — create from a prompt, rewrite slides, speaker notes, image generation
  • OneNote — note-taking AI, knowledge base queries, cross-notebook search
  • SharePoint — page authoring, site agents, document discovery
  • Loop — collaborative components with optional Copilot agents

Copilot Chat is the cross-app surface — when your question spans multiple apps or you don't know which file holds the answer, Chat is the right entry point. With paid tier and Graph access, it can reach across all your content in a single conversation. Without paid tier, it stays at chat-and-web-grounding only.

Two newer surfaces are worth knowing about: Copilot Pages (live collaborative documents born from Copilot conversations) and Copilot Notebooks (persistent project workspaces with their own knowledge layer). Both extend Copilot beyond single-turn chat into sustained collaborative work.

The single biggest win per app

  • Outlook — Summarising a long email thread in one click
  • Teams — Recap a meeting you missed (or attended and need to verify)
  • Word — Draft a project update from a brief in 30 seconds
  • Excel — Ask 'what are the top 3 trends in this data?' on a properly formatted table
  • PowerPoint — Generate a deck from a Word doc or web URL
  • OneNote — Synthesise messy notes into structured output
  • SharePoint — Find the right policy doc without keyword wrestling
  • Loop — Build a live project tracker that updates everywhere it's shared

Copilot Chat — The Hub
The cross-app entry point

Copilot Chat at m365.cloud.microsoft is the cross-app entry point. With paid tier and Graph access, it can reference content across all your emails, documents, meetings, and calendar in a single conversation. The model selector exposes Quick Response (fast) and Think Deeper (slower, better reasoning). The / command references specific files, meetings, and people.

✨ QUICK RESPONSE VS THINK DEEPER
Use Quick Response for everyday drafting and summarising — fast and good enough. Switch to Think Deeper for analysis, multi-step logic, or complex reasoning. Think Deeper is noticeably slower; don't default to it for short tasks.
🎯 PICK THE RIGHT MODE FOR THE TASK
Quick Response is the right default — fast, capable, good enough for 80% of tasks. Switch to Think Deeper when the prompt involves multi-step reasoning, code analysis, trade-off evaluation, or anything where you'd accept a 20-30 second wait for a better answer.

The / command is the underrated power feature. Type / in Copilot Chat and start typing a file name, meeting title, or person — Copilot searches your tenant content and lets you reference up to 3 items in a single prompt. This is the difference between 'analyse a spreadsheet' (which gives Copilot nothing to work with) and '/Q3 Budget Review — what are the 3 biggest variances?' (which gives Copilot the data plus the precise question).

Agents show up in Copilot Chat as @-mentions. If your organisation has deployed custom agents in Copilot Studio, you'll see them as @SalesAgent, @PolicyHelper, etc. These are specialised Chat presets — pre-briefed on a domain, given specific tools and knowledge. Same Chat surface, tighter focus.

Agents and Copilot Studio
Tailored Copilot for specific workflows

Beyond the built-in Copilot, you can build custom agents in Copilot Studio. An agent has its own scope (a specific domain), knowledge sources (specific docs/sites), actions (Power Automate flows), and personality (system prompt). Agents deploy to Teams, Copilot Chat, SharePoint sites, or public websites.

  • Declarative agents — built in Copilot Studio, no code
  • Custom-code agents — built via the Microsoft 365 Agents SDK for advanced scenarios
  • Pre-built agents — Microsoft and partner agents available in the marketplace
  • Agent 365 — the unified governance console for every agent in the tenant

The 2026 shift in agents is that they're no longer experimental. Agent Mode in Word/Excel/PowerPoint went GA in April 2026. Copilot Studio's no-code builder is mature. Microsoft Agent 365 (GA 2026) is the unified governance layer — IT can now see every agent in the tenant, audit every action, set scope policies, and decommission stale agents through one console.

For most organisations, the agent rollout shape is: 60 days of internal exploration (champions building simple agents in Copilot Studio for their own workflows), then a formal governance review (which agents should be promoted to tenant-wide, which should be sunset), then a controlled production rollout for the survivors.

When to build vs when to buy

Microsoft and partners ship pre-built agents through the Copilot agent marketplace. Always check there first — if a Salesforce, ServiceNow, or HR-specific agent already exists for your scenario, it's almost always faster to adopt than to build. Build custom in Copilot Studio when your scenario is genuinely org-specific.

  • Standard scenario (CRM, HR, IT helpdesk) — check the marketplace first
  • Industry-specific knowledge — usually requires custom build
  • Workflow grounded in your unique data — custom build via Studio
  • Mission-critical agents — start with a managed partner build, not a one-person side project

Governance, Security, Compliance
What admins need to know

Copilot inherits your existing M365 security model rather than replacing it. Sensitivity labels, DLP policies, conditional access, audit logging — all continue to apply. That means a tenant with sloppy permissions will surface that sloppiness via Copilot, but also that a tenant with disciplined governance gets Copilot for free, with no additional security burden.

  • Permissions inheritance — Copilot only sees what the user can already see
  • Sensitivity labels — propagate from sources to Copilot-generated content
  • Data residency — Copilot processing stays in your tenant's region
  • Audit logging — every interaction is logged for compliance
  • DLP — Purview policies apply to Copilot the same as direct file access
  • Certifications — ISO, SOC, HIPAA, GDPR, plus industry frameworks
  • Agent 365 — the central console for agent-level governance
⚠️ PERMISSIONS HYGIENE MATTERS MORE THAN EVER
Copilot doesn't break your permission model — but it does make sloppy permissions much more visible. If a confidential file was shared too widely, Copilot will surface it the first time anyone asks a relevant question. Audit your top 20 SharePoint sites for over-sharing before broad Copilot rollout.
🛡️ COMPLIANCE POSTURE
Microsoft 365 Copilot is certified or attested under ISO 27001/27017/27018/27701, SOC 1/2/3, HIPAA (under BAA), GDPR, plus financial services and public sector frameworks. Your existing M365 compliance posture extends to Copilot. Government tenants run in the Government Community Cloud (GCC) variants.

The IT runbook for ongoing operations

  • Weekly — Review audit logs for unusual activity (especially first month)
  • Monthly — Active user trends per function; cost variance; agent inventory
  • Quarterly — Sensitivity label coverage audit; permissions over-share scan
  • Semi-annually — Renewal readiness; documented ROI by function
  • Annually — Full compliance posture review against current frameworks

The Copilot agent ecosystem matured significantly through 2025-2026 — Agent Mode in Word/Excel/PowerPoint GA, Copilot Studio no-code builder GA, Agent 365 unified governance console GA. From built-in agents to custom Studio-built agents, the platform now spans the full spectrum.

🏛️ AGENT 365 — THE GOVERNANCE LAYER
Agent 365 (GA 2026) is where IT sees every agent in the tenant — built-in, custom, Studio, partner. Audit logs, scope policies, decommission tooling. Set up before agents proliferate.

Copilot Agents

Three agent classes: declarative agents (built in Copilot Studio, no code), custom-code agents (via Microsoft 365 Agents SDK), and pre-built agents (Microsoft and partner agents in the marketplace).

  • Declarative agents — no-code, fast to build, Copilot Studio
  • Custom-code agents — full SDK, for advanced scenarios
  • Pre-built agents — marketplace of Microsoft and partner agents
  • Agent 365 — tenant-wide governance console for every agent
  • Deploy to Teams, Copilot Chat, SharePoint, or public website

Copilot Studio

The no-code agent builder. Five components: topics, knowledge sources, actions, system prompt, channels. Build an agent in 20-30 minutes for a focused domain.

  • Topics — named conversation flows the agent handles
  • Knowledge sources — 1-3 SharePoint sites or doc libraries (curated, not all-of-SharePoint)
  • Actions — Power Automate flows or API calls the agent can trigger
  • System prompt — the 5-part template: Role, Scope, Tone, Limits, Format
  • Channels — Teams, Copilot Chat, SharePoint, website, custom

Copilot vs ChatGPT

When to use Microsoft Copilot, when to use OpenAI ChatGPT, and how to deploy both well. Most mature deployments use both.

  • Copilot wins: in-flow M365 work, tenant-grounded queries, M365-native workflows

Common Mistakes & Fixes
What goes wrong — and how to avoid it

Most AI workflows that 'don't work' fall into one of these patterns. The fix is almost always sharper context and stricter review, not switching models or tools.

  • Treating Copilot Master Guide as a finished answer rather than a draft to review
  • Vague prompts that don't specify audience, format, or what you want changed
  • Forgetting to give it context — the file, the brief, the constraints
  • Skipping the verify step — always check numbers, dates, names, and policy claims
  • Using it for tasks where a 30-second human action would be faster

✅ DO THIS

  • Provide context — the file, the brief, the audience, the constraints
  • Iterate; don't just accept the first output
  • Always review numbers, names, dates, and policy claims
  • Treat AI as a fast draft generator, not an answer engine
  • Capture what works so you can replicate it
  • Match the model to the task — fast modes for drafts, reasoning modes for analysis

❌ AVOID THIS

  • Sending AI output without reading it end-to-end
  • Vague prompts with no audience, format, or success criteria
  • Assuming AI can see files or context it hasn't been given
  • Using AI for tasks faster done manually in under a minute
  • Treating numbers, quotes, or citations as verified without checking
  • Defaulting to the slow reasoning mode for every task
