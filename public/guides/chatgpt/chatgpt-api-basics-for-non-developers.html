What is the API?
Same intelligence, programmable

The API is the same GPT-5.5 family as ChatGPT — but instead of a chat interface, you send requests programmatically. You pay per token (chunks of text). Cheap for occasional use; meaningful at scale.

  • Pay-as-you-go — no monthly subscription minimum
  • Models: GPT-5.5 Instant, GPT-5.5, GPT-5.5 Pro
  • Inputs and outputs measured in tokens (~750 words per 1000 tokens)
  • Pricing varies by model and reasoning tier

API pricing matters at scale. For low-volume use (under 100K tokens per day), the API is meaningfully cheaper than ChatGPT Plus. For high-volume use, the math flips — Plus's flat rate caps your downside while the API meters every token. The crossover is roughly 1M tokens per month per user.

The Advisor pattern is the cost-control unlock for high-volume use. GPT-5.5 executes most steps, GPT-5.5 Pro advises on the hard ones, dropping average cost-per-task by 50-70% with near-Pro quality. This is the difference between AI workflows being affordable at scale and being a budget line that grows with usage.

How to estimate cost before building

Run 100 sample tasks first. Multiply by your expected volume. Compare to alternatives (consumer Plus, contractor labour). Decide if the math works.

  • Sample size: 100 tasks. Measure tokens in and out per task.
  • Multiply by expected monthly volume
  • Add safety margin (50%) for variance
  • Compare to: (a) consumer Plus subscription, (b) contractor/employee time saved
  • ROI multiple: typically 15-30x at moderate volumes

Authentication and Keys
The basics
  • Get an API key from platform.openai.com
  • Treat it like a password — never commit to git, never paste in chat
  • Rotate quarterly
  • Set a usage limit on your account to cap surprise bills

✅ DO THIS

  • Get API key from platform.openai.com → API keys
  • Treat key like a password — never commit to git
  • Rotate quarterly
  • Set hard usage caps on your account
  • Use environment variables (.env files) not inline strings
  • Separate keys per project/use case for cost tracking

❌ AVOID THIS

  • Pasting API keys in chat, slack, or shared documents
  • Committing .env files to git (add to .gitignore)
  • Using a single key across all projects (makes cost attribution impossible)
  • Forgetting to revoke keys for departed staff
  • Skipping the usage cap — surprise bills can be 5-figure
  • Using consumer Plus credentials for API calls — they don't work for the API

The Advisor Pattern
Cost control for agentic flows

For multi-step workflows, set GPT-5.5 as the everyday executor and route only hard sub-problems to GPT-5.5 Pro. Near-Pro quality, dramatically lower cost. Available via the API with a single parameter.

Honest Limits
Where the API isn't the right tool
  • Real-time interactive UX — latency is too high for sub-second response needs
  • Highly regulated outputs — always need human review before customer-facing or legal
  • Tasks where consistency matters more than capability — small fine-tuned models often win
  • Anything where one bad output causes major harm — the API is high-variance

Where the API isn't the right tool

The API isn't a silver bullet. Specific patterns produce worse outcomes than alternatives — knowing them upfront prevents painful mid-build pivots.

  • Real-time interactive UX — latency too high for sub-second response needs
  • Highly regulated outputs — always need human review for legal/medical/financial
  • Tasks where consistency matters more than capability — fine-tuned small models often win
  • Anything where one bad output causes major harm — variance is too high
  • Tasks faster done manually in under a minute — overhead of API call exceeds saving

Common Mistakes & Fixes
What goes wrong — and how to avoid it

Most AI workflows that 'don't work' fall into one of these patterns. The fix is almost always sharper context and stricter review, not switching models or tools.

  • Treating ChatGPT API Basics for Non-Developers as a finished answer rather than a draft to review
  • Vague prompts that don't specify audience, format, or what you want changed
  • Forgetting to give it context — the file, the brief, the constraints
  • Skipping the verify step — always check numbers, dates, names, and policy claims
  • Using it for tasks where a 30-second human action would be faster

✅ DO THIS

  • Provide context — the file, the brief, the audience, the constraints
  • Iterate; don't just accept the first output
  • Always review numbers, names, dates, and policy claims
  • Treat AI as a fast draft generator, not an answer engine
  • Capture what works so you can replicate it
  • Match the model to the task — fast modes for drafts, reasoning modes for analysis

❌ AVOID THIS

  • Sending AI output without reading it end-to-end
  • Vague prompts with no audience, format, or success criteria
  • Assuming AI can see files or context it hasn't been given
  • Using AI for tasks faster done manually in under a minute
  • Treating numbers, quotes, or citations as verified without checking
  • Defaulting to the slow reasoning mode for every task
