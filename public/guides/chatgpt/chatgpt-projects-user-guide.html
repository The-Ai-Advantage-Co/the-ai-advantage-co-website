01

What is ChatGPT Projects?

ChatGPT's default experience is a flat list of conversations — each one is isolated, starts fresh, and requires you to re-establish context, re-upload files, and re-explain your preferences every time. For one-off questions, that's fine. For ongoing work, it becomes friction. Projects solves this.

A Project is a persistent workspace — a container that holds related conversations, uploaded files, and custom instructions. Everything inside a project shares the same context: files you've uploaded are available in every conversation, your instructions apply automatically, and your conversations are grouped and findable.

Without Projects

Conversations are isolated and flat. You must re-explain your role, re-upload documents, and re-state preferences in every new chat. Context from previous conversations is lost.

With Projects

All conversations in a project share the same uploaded files and custom instructions. You drop into a conversation and ChatGPT already knows the context — no re-setup needed.

When Projects Make the Biggest Difference

Projects shine for any recurring or multi-session work: client engagements, ongoing research topics, content series, product lines, legal matters, or internal processes. If you've ever started a new chat by pasting in the same background paragraph or re-uploading the same document, that work belongs in a project.

02

Creating & Organising Projects

Creating a project takes under a minute. The more important decision is how to structure your projects — the right taxonomy means you'll always know where to go, and ChatGPT will always have the right context.

1
Open the Projects panel

In the left sidebar, look for "Projects" above your conversation history. Click it to expand the projects panel. If you don't see it, look for a folder icon or a "New project" option.

2
Create and name your project

Click "New project" (or the + icon). Give it a clear, specific name. "Client A — Q3 Strategy" is better than "Work Stuff". The name appears in your sidebar and helps ChatGPT understand the context scope.

3
Add an icon or colour (optional)

Some interfaces allow a custom icon or emoji and accent colour for each project — useful for quick visual identification when you have multiple projects active. Choose something that represents the topic or client.

4
Start your first conversation inside the project

With the project open, create a new conversation. It will automatically be saved inside the project. Files you upload here will be available to all future conversations in this project.

How to Structure Your Projects

By Client or Account

One project per client. All research, writing, analysis, and correspondence for that client lives together. Upload their brand docs, briefs, and past deliverables once — reference them always.

By Topic or Subject

Ongoing research areas benefit from topic-based projects. "AI Regulation Research", "Competitor Analysis", "Personal Finance Learning" — everything on that subject in one place.

By Project or Campaign

Time-bounded projects (a product launch, a report, a conference) work well as projects. Archive when complete; the whole body of work stays together for future reference.

By Role or Function

"My Writing" for content work. "Legal Matters" for contracts and compliance. "HR Processes" for people management tasks. Role-based projects work well when the context (tone, terminology, files) is consistent across many different tasks.

Project Naming Best Practice

Use a consistent naming convention from the start: "[Client/Topic] — [Scope/Year]" works well. "Acme Corp — 2025", "AI Research — Ongoing", "Blog Content — Q3". Consistent naming makes the project list scannable at a glance.

File Management Best Practices

Upload the Right Foundation Files

Think about what ChatGPT needs to know to work on this project: brief documents, style guides, reference data, existing reports, brand guidelines, regulatory frameworks. Upload these once at project creation.

Update Files When Content Changes

Replace outdated files rather than adding new versions alongside old ones. Having "Report-v1.pdf" and "Report-v2.pdf" both uploaded creates confusion. Remove the old version before uploading the new one.

File Types That Work Well

PDFs, Word docs, Excel files, PowerPoints, plain text, and CSVs all work. For best results, text-heavy documents (briefs, reports, specifications, data exports) give ChatGPT the most useful content to reference.

Size and Limits

Each file has an upload size limit (typically 512 MB). Projects have a storage limit that varies by plan. For very large datasets, consider uploading a summarised or filtered version rather than the full raw file.

The "Context File" Technique

Create a plain text file called "Project Context.txt" and upload it as the first file in every project. It contains: the project goal, key terminology specific to this client or topic, preferred output formats, and any standing assumptions. ChatGPT will reference this automatically, reducing the need to re-explain basics in every conversation.

Custom Instructions per Project

Global custom instructions apply to all your ChatGPT conversations. Project-level instructions override them for that project — letting you set a completely different tone, persona, or set of rules depending on what you're working on.

Project Instructions Q3 Market Analysis
What should ChatGPT know about this project?
You are supporting a quarterly market analysis for a UK fintech consultancy. All data and documents relate to Q3 2025 UK market conditions. Always: - Reference figures from the uploaded data files when relevant to the analysis - Use British English spelling throughout all outputs - Present financial figures in GBP unless specifically asked to convert - Flag clearly when you are drawing on your training data rather than the uploaded documents - Ask one clarifying question before starting any analysis if the scope is ambiguous Output style: concise, analytical, structured with clear headings. Suitable for senior stakeholder presentations. Avoid marketing language.

Layer Instructions with Uploaded Files

For longer, more detailed context (tone of voice guide, brand playbook, detailed background), upload it as a file rather than cramming it into the instructions field. Use the instructions field for behavioural rules (what to always/never do, how to format output) and let the files carry the substantive content.

Instructions Don't Replace Per-Message Guidance

Project instructions set defaults — they don't guarantee ChatGPT will apply every rule every time, especially in long conversations. For critical requirements (don't include X, format as Y), reinforce them in the message where they matter most. Treat instructions as strong defaults, not inviolable rules.

05

Conversations Within Projects

Each project can contain many conversations. Understanding how conversation context works inside a project — and how it doesn't — is key to using projects effectively.

Important: Context Doesn't Carry Between Conversations

Files and instructions are shared across all project conversations — but the conversational context (what was said, what was decided, what was produced) is limited to each individual conversation. Conversation A and Conversation B in the same project can both see the uploaded files, but neither can see what the other discussed. Plan your conversations accordingly.

What IS Shared Across Conversations

Uploaded project files · Project custom instructions · Project name and metadata · Any other files you've added to the project

What Is NOT Shared

The conversational history of other conversations · Decisions or outputs produced in other chats · Context established mid-conversation in a sibling conversation

Managing Conversations Well

1
Name conversations descriptively

ChatGPT auto-names conversations, but you can rename them. Use names like "Market sizing analysis — March", "Client presentation draft v2", or "Legal review — Section 4". This makes the project history navigable weeks later.

2
One conversation per task or session

Start a new conversation for meaningfully different tasks within a project. Don't pack everything into one endless conversation — the longer a conversation gets, the more performance degrades. New conversations are cheap; context confusion is expensive.

3
Carry forward key outputs via files or paste

When you produce something important in Conversation A that Conversation B will need (a framework, a set of decisions, a summary), save it as a text file and upload it to the project. Now it's available as a project file in all future conversations.

4
Move conversations between projects

If a conversation ends up belonging to a different project than the one it started in, you can move it. Look for the conversation options menu (⋯) and select "Move to project". This keeps your organisation clean.

The Running Notes File Technique

Maintain a "Project Notes.txt" file in the project. After significant conversations, add the key outputs, decisions, and action items to this file and re-upload (replacing the previous version). Any new conversation can then be started with: "Read the Project Notes file — that's the current state of this project." Instant context continuity.

06

Collaboration & Sharing

On Team and Enterprise plans, projects can be shared with other users — creating collaborative workspaces where a team shares the same files, instructions, and organisational structure.

Shared Project Files

All team members with access to the project can see and use the uploaded files. One person uploads the brief, everyone can reference it — no more emailing documents back and forth before ChatGPT sessions.

Shared Instructions

The project's custom instructions apply to every team member who uses the project. Consistent tone, formatting, and rules — without each person needing to configure their own settings.

Individual Conversations

Even in shared projects, each team member's conversations are their own — unless explicitly shared. You can see the project structure and files, but not colleagues' individual chat histories.

Access Control

Admins on Team/Enterprise can control who has access to which projects — useful for client confidentiality or department separation. Not all team members need access to every project.

Availability Note

Shared projects are a Team and Enterprise feature. On Plus (individual) plans, projects are personal and private. If your organisation uses ChatGPT Enterprise, your admin controls which projects can be shared and with whom.

Advanced Techniques

These techniques take Projects from useful filing system to a genuine productivity infrastructure — making ChatGPT feel like a knowledgeable assistant who already understands your work.

The Briefing Document Stack

Build a structured set of reference files for complex projects. Each file serves a different purpose:

Multi-Project Workflows

Cross-Project Output Flow

Produce a deliverable in one project (e.g. a research report in "Market Research"), then bring it into another project (e.g. "Client A — Proposal") by uploading it as a file. The output becomes input elsewhere.

Template Projects

Create a "Template — New Client" project with standard files and instructions. When you win a new client, duplicate the structure (manually), rename it, and swap in client-specific documents. Instant setup.

Instruction Layering Pattern

Use a three-layer instruction system for maximum control:

Layer 1 — Global Custom Instructions

Universal preferences: your name and profession, languages you work in, general output format defaults, fundamental tone. These apply everywhere as the base layer.

Layer 2 — Project Instructions

Project-specific overrides: client context, specialised vocabulary, project-specific rules and constraints. These override Layer 1 where they conflict.

Layer 3 — Per-Message Instructions

Task-specific overrides for a single output: "For this email, use a more formal tone." These are the most specific and override everything for that one message.

08

Common Mistakes & Fixes

❌ Assuming ChatGPT can see what happened in other conversations within the project
Fix: Only files and instructions are shared across conversations in a project — not conversational history. If Conversation A produced a decision or output that Conversation B needs, export it as a text file and upload it to the project, or paste the key content at the start of the new conversation.

❌ Using the global custom instructions field for project-specific rules
Fix: Global custom instructions apply to every conversation — not just project conversations. Keep global instructions truly universal (your name, profession, language). Use project-level instructions for anything specific to that project, client, or domain. Cluttering global instructions with project rules creates conflicts.

❌ Uploading files to a conversation instead of to the project
Fix: Files uploaded inside a conversation are only available for that conversation — they don't persist in the project. Navigate to the project's Files section and upload there. Files uploaded at the project level are available in all conversations. It's easy to make this mistake — check where you're uploading every time.

❌ Creating one giant conversation for all project work
Fix: Very long conversations degrade in quality as the context window fills up. Start a new conversation for each distinct task or session. Since project files and instructions persist, starting fresh doesn't mean losing context — it means working with a fresh, uncrowded context window on every task.

❌ Leaving outdated file versions in the project
Fix: When you update a document (new version of a report, revised brief, updated data), remove the old file before uploading the new version. If both versions are present, ChatGPT may reference the wrong one or get confused by contradictory information. Replace, don't accumulate.

❌ Writing project instructions that are too vague to be useful
Fix: "Be professional" doesn't give ChatGPT actionable guidance. Specific instructions work: "Always use bullet points for lists, headers for sections, and keep responses under 300 words unless asked otherwise. Use formal British English. Never use contractions." Test your instructions by starting a conversation and seeing if ChatGPT's first response reflects them.

Suggested Prompts

Project Kickoff Prompt
I'm starting a new project and I've uploaded the key reference documents. Before we begin any specific tasks, please: (1) read all uploaded files and confirm what you have access to, (2) summarise the project as you understand it in 3–4 sentences, (3) flag any gaps or ambiguities in the documents that I should address, and (4) ask any clarifying questions that would help you serve this project better.
Context File Generator
Help me write a "Project Context" file for this project that I can upload to keep all future conversations oriented. Based on what you know so far, draft a plain text file covering: project name and goal, key stakeholders and audience, important terminology and definitions, standing assumptions, output preferences, and anything ChatGPT should always keep in mind when working on this project.
Project Instructions Writer
Help me write effective project instructions for a new ChatGPT project. The project is: [describe project]. The main types of tasks I'll use it for are: [list tasks]. The audience for outputs is: [describe audience]. Draft project instructions (under 1500 characters) that cover role, tone, standing rules, output format, and when to ask clarifying questions.
New Conversation Orientation
Before we start, please read all the project files and give me a one-paragraph reminder of where this project stands. What are the key documents I've uploaded, what are the standing rules from the project instructions, and is there anything in the files that suggests where we left off or what the current priorities are?
Progress Note Generator
This conversation has produced some important outputs and decisions. Help me write a brief progress note (under 200 words) that captures: (1) what we accomplished in this session, (2) any key decisions made, (3) any open questions or action items, and (4) recommended next steps. I'll add this to the project's running notes file.
Project Audit
Review all the files currently uploaded to this project and tell me: (1) which files are most and least likely to be current/relevant, (2) any apparent gaps — important topics or references that should probably have a file but don't, (3) any files that seem to duplicate or contradict each other, and (4) any recommendations for how to improve the project's file structure.

Conversation 1 — Kickoff Analysis
You: Read all uploaded files and summarise what you know about this client, their current position, and what they're asking us to help with. Flag any gaps.
✦ Meridian Retail is a 47-store UK fashion retailer (from the brief) with £124M turnover in 2024 (annual report, p.3). Gaps flagged: No information on current tech stack, no customer data or personas, and the brief mentions a "previous digital initiative" that was discontinued — understanding why would be important context.
Conversation 2 — Competitive Landscape (separate conversation, same project)
You: Using the project files, remind yourself of Meridian's position, then search the web for current competitive intelligence on mid-size UK fashion retailers' digital strategies in 2025. Specifically: what are NEXT, Reiss, and Fat Face doing that Meridian isn't?

Key gaps vs competitors: NEXT's Directory loyalty integration (27M members, 45% repeat purchase rate [1]); Reiss's app-first clienteling approach for VIP customers [2]; Fat Face's successful in-store scan-to-web inventory tool (launched Q4 2024) [3]. Meridian's brand guidelines suggest strong lifestyle positioning that these three don't own — potential differentiation angle.
What the Project Architecture Achieved

Two separate conversations, both with full access to Meridian's uploaded documents. Conversation 2 didn't need to re-explain who Meridian is or what they're trying to do — that context came from the project files automatically. As the engagement grows, every new conversation starts with the same foundation.

Your Roadmap

01

Create Your First Project

Pick an ongoing piece of work — a client, a research topic, a content series. Create a project, upload 2–3 relevant files, and run your next task inside it instead of in a standard conversation.

02

Write Project Instructions

For that same project, write specific custom instructions: role, tone, standing rules, output format. Test them by starting a conversation and seeing if the first response reflects your settings.

03

Build the Context File Stack

Create a Project Context.txt file for your most important project. Include goal, audience, terminology, and standing assumptions. Upload it and start every new conversation by asking ChatGPT to read it first.

04

Turn Projects into Infrastructure

Structure all your recurring ChatGPT work into projects. Audit your conversation history — identify what should have been a project — and build those structures proactively for future work.
