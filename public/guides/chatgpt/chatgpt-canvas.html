What is ChatGPT Canvas?
The side-by-side editing mode for long-form writing and code

Canvas is ChatGPT's collaborative editing mode — when you start a long-form writing or code task, ChatGPT opens a Canvas alongside your chat. You see your prompts on one side and the model's output on the other as a live document you can edit inline.

Best for: any writing or code task that's longer than a few paragraphs, or where you want to iterate on specific sections without rewriting the whole thing.

How to Open Canvas
Two paths in
  • Implicit — for long writing/code tasks, ChatGPT opens Canvas automatically
  • Explicit — click the Canvas button in any chat to open one

Two ways Canvas opens

Canvas opens implicitly for long-form tasks or explicitly on demand. The implicit trigger is what most users encounter first; the explicit trigger is for when you know upfront you'll want it.

  • Implicit — for long writing/code tasks, ChatGPT opens Canvas automatically
  • Explicit — click the Canvas button in any chat to open one
  • Convert mid-conversation — switch a normal chat to Canvas at any point
  • Carries existing content — current draft populates the Canvas
  • Works on web, desktop apps; mobile experience improving

04
Targeted Section Editing
The biggest Canvas unlock

Select a paragraph, sentence, or code block. Right-click and ask for a specific change — 'tighten this', 'rewrite for a non-technical audience', 'fix this bug'. The change applies only to the selection.

  • Select text → right-click → ask for specific change
  • Select a code block → right-click → 'add error handling'
  • Select a paragraph → right-click → 'rewrite in a different tone'
🎯 TRAIN THE RIGHT-CLICK HABIT EARLY
Most users new to Canvas miss right-click and over-rely on full-document regenerations. Train the right-click habit explicitly — it's the difference between Canvas being fancy chat and Canvas being a genuine editing surface.

The right-click pattern that unlocks Canvas

The right-click targeted editing is what separates Canvas from fancy chat. Select text. Right-click. Ask for a specific change. The change applies only to the selection — surrounding content stays intact.

  • Select text → right-click → ask for specific change
  • Selections can be sentence, paragraph, or multi-paragraph
  • Common right-click asks: tighten, lengthen, polish, rewrite for [audience], translate
  • Code right-clicks: refactor, add error handling, simplify, add tests, fix bug
  • Iterate quickly — the targeted edit pattern is meant for multiple passes

Coding in Canvas
Where Canvas shines for code

For code longer than ~30 lines, Canvas is dramatically better than chat. You see the full code, can edit inline, and request targeted changes ('refactor this function', 'add tests for this'). Multi-file code is still better in Cursor or another IDE.

💻 WHEN CANVAS BEATS AN IDE
Canvas is best for self-contained scripts, prototypes, and code review. For multi-file projects with imports and dependencies, you still want a real IDE.
💻 CANVAS VS CURSOR
Canvas is excellent for self-contained scripts and code review. For multi-file projects with imports, dependencies, and a real test harness, dedicated IDEs (Cursor, VS Code with Copilot) still win. Canvas is the right tool for prototypes; IDEs are the right tool for sustained engineering.

Where Canvas shines for code

Canvas is meaningfully better than chat for code longer than ~30 lines. You see the full code, can edit inline, and request targeted changes ('refactor this function', 'add tests for this'). Multi-file code work belongs in an IDE.

  • Self-contained scripts — Canvas is dramatically better than chat
  • Code review — paste code, ask for review, get targeted suggestions
  • Prototyping — iterate quickly with right-click edits
  • Test generation — 'add tests for this function' on selected code
  • Refactoring — 'refactor for clarity, keep behaviour identical' patterns
07
Limits
What Canvas isn't
  • Single document — not a multi-doc workspace
  • Plain text outputs — not Word-style rich formatting
  • Export limited — copy out manually or convert via another tool
  • No version history yet — copy intermediate states yourself if needed

✅ DO THIS

  • Use Canvas for any non-trivial writing (>200 words)
  • Use Canvas for self-contained code work
  • Train the right-click pattern explicitly
  • Iterate by section, not by full regeneration
  • Save intermediate states yourself for important versions
  • Use Canvas with the four-element brief structure

❌ AVOID THIS

  • Treating Canvas as fancy chat — under-using right-click
  • Multi-file project work — use a real IDE
  • Long-form structured documents — markdown formatting limits
  • Rich formatting expectations — Canvas is plain text fundamentally
  • Forgetting Canvas history — no built-in version history yet
  • Mixing Canvas and chat in the same session — confusing flow

Common Mistakes & Fixes
What goes wrong — and how to avoid it

Most AI workflows that 'don't work' fall into one of these patterns. The fix is almost always sharper context and stricter review, not switching models or tools.

  • Treating ChatGPT Canvas as a finished answer rather than a draft to review
  • Vague prompts that don't specify audience, format, or what you want changed
  • Forgetting to give it context — the file, the brief, the constraints
  • Skipping the verify step — always check numbers, dates, names, and policy claims
  • Using it for tasks where a 30-second human action would be faster

✅ DO THIS

  • Provide context — the file, the brief, the audience, the constraints
  • Iterate; don't just accept the first output
  • Always review numbers, names, dates, and policy claims
  • Treat AI as a fast draft generator, not an answer engine
  • Capture what works so you can replicate it
  • Match the model to the task — fast modes for drafts, reasoning modes for analysis

❌ AVOID THIS

  • Sending AI output without reading it end-to-end
  • Vague prompts with no audience, format, or success criteria
  • Assuming AI can see files or context it hasn't been given
  • Using AI for tasks faster done manually in under a minute
  • Treating numbers, quotes, or citations as verified without checking
  • Defaulting to the slow reasoning mode for every task
